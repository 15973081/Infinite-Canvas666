## 合理共享与尚未收拢的协调

模板/词库与本地预设仍各有五个内容或缓存绑定，由 library 的现有存储流程管理；素材内容、模型配置、工作流缓存也具有共享读取价值。它们不能仅因留在入口就被视为重复 UI 状态，也不应通过复制来私有化。

`nodes`、连接、文档、viewport 和 settings 是共享业务数据，但其多入口写入仍需要后续梳理；“合理共享数据”不等于“当前所有写入路径都已合理”。选择、composer、撤销、生成快照与保存之间的协调，是当前较重的维护成本来源。生成任务、锁、同步和保存可能长于面板生命周期，不能套用关闭面板即销毁的规则。

渲染缓存、几何队列属于派生数据和调度；多数已有 workspace 操作入口，仍有少量入口重置。静态常量表不作为整理对象。管理视图和 library 多选状态多数已经局限于单模块，其优先级不能只由变量数量决定。

## 下一阶段：Smart 音频预览会话

当前证据（行号对应本次基线）：

- `smart-workspace.js:3513–3524` 的外部引用音频分支自己关闭编辑器、释放播放器、清空目标、写标题、创建并配置 audio、插入 DOM、打开模态窗口；与 `smart-results.js:30–50` 的节点音频打开流程重复。
- `smart-document.js:784、828` 和 `smart-workspace.js:547、4527` 直接组合节点 ID 与 DOM 的 `open` 类，分别处理删除、虚拟化保留和 Escape。
- `smart-canvas.js:25–27、240` 保留三个 DOM 引用和一个音频状态对象。`smart-canvas.js:592–595` 已有页面离开清理，不能宣称缺少这项机制。

建议在 Smart results 中设立音频功能唯一所有者，保留现有函数名薄委托。私有化开关、节点/外部来源、标题、三个专属 DOM、原生 audio 和自身监听；冻结快照分别表达面板打开与目标有效。

提供完整的节点播放、外部音频播放、关闭、下载、目标查询、目标删除通知、重置和销毁操作。workspace 外部分支收敛为一次 `openExternalAudio({url, name})`；删除、虚拟化和 Escape 使用 `closeForNodes()`、`isPreviewingNode()` 或只读打开状态，不再写内部字段或读专属 DOM。接口名称可在实施时调整，业务操作必须完整。

节点目标记录画布、节点及目标音频身份，执行时核对仍有效；外部 URL 作为独立来源。关闭不依赖目标仍有效，迟到媒体事件不能恢复旧会话。移交已有 pagehide 责任，保留缓存返回后不自动重新打开或恢复播放的行为。

保持以下差异：节点打开原有选择与查看计时行为；引用预览 `try/finally` 恢复选择；原权限及保存触发次数；无节点外部音频目前没有节点关联的下载行为。选择和节点数据继续归原流程，不能趁封装重构全局选择。共享键盘处理器只委托查询和关闭，音频功能不移除其他工作区监听。

验收看实际协作收益：

1. 音频会话和专属 DOM 的直接写入由两个模块收敛到一个；workspace 的外部打开分支只表达一次操作意图。
2. 节点、分组音频和外部 URL 入口保持内容、选择恢复、下载及保存次数；只读行为不变。
3. 删除/替换目标、切画布后旧目标不可操作；面板仍能用真实 Escape、遮罩和关闭按钮退出。
4. 重复打开/绑定、切源、关闭后迟到媒体事件不累积播放器或监听；释放暂停、清源、load、移除播放器，并清理自身监听。
5. pagehide、缓存返回和永久销毁保持既有页面行为；图片/视频预览、编辑器、全景、生成与保存核心不变。
6. 实施后补真实音频浏览器验收，并运行全量 JS、相关 Python 和差异检查。本轮不实施。
