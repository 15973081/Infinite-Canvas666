# 账号注销与数据边界

成员菜单“个人数据”中先导出需要保留的数据，再输入当前密码与完整确认文字“注销并删除本人数据”，提交注销。每个账号五分钟最多核对十次密码。服务器按当前登录成员处理，不能指定其他成员注销。

服务器先检查管理员职责、进行中的生成/对话/备份任务、附件状态和共享引用。最后一位平台或活动空间管理员必须先交接职责；进行中的任务先完成或核对。仍被共享画布、素材、任务、历史备份或他人对话引用的附件会阻止注销，返回本人的附件 ID，不泄露他人的对话或正文。应先处理引用，必要时联系空间管理员完成交接。本功能不强行删除他人的引用。

条件不满足时事务回滚：本人对话、附件及登录保持原状，尚未接受注销意图。条件满足后，先把最小注销意图及准确附件版本写入独立删除账本，再在同一数据库事务中完成：

- 删除各空间本人私有对话及其中的 Skill 文字快照、个人 Skill 启用偏好和个人草稿复制回执。
- 将本人对话附件和预览标记为停止访问、撤销共享，加入已有持久化附件删除队列。存储失败由后台继续重试，注销响应给出待清理附件数量。
- 撤销所有工作台和管理会话及激活入口，释放编辑租约，移除角色、空间成员关系和在线状态。
- 成员记录进入 `closed`，清除密码、头像、原用户名与显示名，保留不可登录的匿名标识及必要外键。已发布 Skill 留给空间管理，署名改为“已注销成员”。管理后台不能把该成员恢复为活动成员或重置其凭据。

共享画布和空间资源、他人的对话、任务结果、费用账本、历史费用归属及必要审计独立保留。空间编辑快照属于共享资源，也不会随个人注销删除。已下载副本、原有备份字节和供应商收到的内容按独立保留规则处理，不能承诺从外部副本抹除。

账本写入失败时不接受注销，数据库变更回滚；若账本已经接受注销而数据库提交中断，账本立即阻止登录及本人附件访问，后台独立清理循环修复注销。恢复旧备份同样重放注销、私有正文及准确附件版本，不重新激活账号。若备份中的管理员交接状态过旧，恢复拒绝开放，需核对交接并使用合适的备份，不能为了恢复管理入口取消注销。

部署时应用 `032_account_closure.sql`，与既有 `031_chat_attachment_lifecycle.sql` 一起完成正常迁移；配置 API 和所有 worker 共用的持久化 `DELETION_LEDGER_ROOT` 并保持当前账本连续。后台循环每三十秒检查附件队列与已接受意图的修复，不占生成任务槽位。当前完整恢复工具支持 filesystem 本地备份包，TOS 原生版本全库恢复仍拒绝开放。
