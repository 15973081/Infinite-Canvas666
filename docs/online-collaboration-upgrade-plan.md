# 线上协作升级计划

更新：2026-09-14。状态：M1/C2/C3 持续实施中；成员/权限、数据库租约、双画布交接与草稿恢复已接入，在线名单、状态订阅与查看页同步已完成本地验收；完整业务迁移与故障联调仍在推进，见[实施记录](management-platform-progress.md)。

基线：`38610de`，PostgreSQL + `.local/cloud` 对象模拟已完成存储验收。此次在其上增加线上成员协作，替代旧计划“暂不引入独立用户身份”的约定。既有存储、两种画布、任务恢复及费用账本继续沿用。

配套扩展：[独立管理平台、空间权限与维护升级计划](management-platform-upgrade-plan.md)。本轮新增管理平台独立部署、多空间分配及自定义角色，替代上一版“仅 default 工作区、固定三角色”的范围；画布锁仍按本计划 C2/C3 升级。

## 1. 目标与范围

采用“个人身份 + 共享工作区 + 单人编辑、多人查看”。成员仅进入管理员分配的空间，同一空间内按权限共享画布和素材，空间之间隔离；同一成员可加入多个空间并拥有不同角色。历史资源留在 `default` 空间，不自动复制或对所有成员开放。

- 普通画布和智能画布统一身份、锁状态、接手和断线规则。
- 用成员昵称、头像和必要的成员短编号展示身份，普通协作界面不展示 IP。
- 一个账号可以在多设备登录，但同一张画布同时只有一个有效编辑会话。
- 画布锁在 PostgreSQL 中保存；持锁身份、权限、到期时间、锁代次和画布 revision 共同约束写入。
- 继续使用 `.local/cloud` 的 PostgreSQL 和对象模拟验收，不创建云资源、不迁移真实用户数据、不调用付费模型。
- 首版业务端仍部署一个 Web 进程，管理站点及管理 API 进程独立部署。数据库锁须经多连接竞争验证；跨实例实时广播和其他内存状态的改造另行安排，不能仅凭锁落库宣称整站支持多实例。

本轮纳入多空间及自定义角色；暂不包含公开注册、邮箱验证/找回密码、逐画布自定义权限、余额扣费、同时编辑同一画布的 CRDT/OT、Redis 和业务多机部署。

## 2. 现状与修改位置

| 已核对的位置 | 当前行为 | 升级要求 |
|---|---|---|
| `app/services/auth.py` | 共享入口账号，登录会话保存在本机 SQLite | 成员及线上登录会话进入 PostgreSQL，服务端解析当前成员和工作区角色 |
| `app/state.py`：`CanvasLockManager` | 内存字典保存锁，以客户端传入的 client_id 区分持有者 | 改用持久化编辑租约；内存仅缓存展示状态，不作写入授权依据 |
| `app/state.py`：`ConnectionManager` | WebSocket 断开会按 client_id 释放锁 | 断开只更新在线状态；释放由显式操作、会话撤销或租约到期决定 |
| `app/routers/canvas.py`：画布锁接口 | 接受前端 username/client_id；返回 IP；释放前先生成备份 | 从登录身份识别成员；释放、接管和备份须先校验持锁资格，拒绝伪造和重复副作用 |
| `static/js/canvas.js`、`static/js/smart-canvas.js` | 浏览器昵称、IP 展示、持锁轮询与自动获取 | 统一成员展示；打开默认查看，主动开始编辑；共用协作客户端状态机 |
| `static/js/canvas-api.js`、画布写入接口及服务 | 已有 revision 和任务幂等机制 | 请求携带编辑会话及锁代次；所有相关写入在后端执行一致校验 |
| `app/utils.py`：`safe_user_id`、对话接口 | 接受 X-User-ID，缺省回退 IP | 线上成员模式只使用认证身份确定归属，旧身份走显式映射 |

当前 IP 是展示信息，实际锁归属依据是 client_id。升级同时修正身份可信来源与服务端写入控制，不能仅替换显示文字。

## 3. 成员、会话与权限

### 成员入口

首版由管理员创建成员，提供一次性激活凭证，成员自行设置密码；不开放匿名注册，不复用共享入口密码给所有成员。激活凭证有期限、只使用一次、仅保存哈希；成员密码沿用经过验证的密码哈希方式。管理员提供重置入口，不读取成员原密码。

首个管理员由受控本机 CLI 初始化，不开放公网“先到先得”初始化接口。线上成员模式启用后，旧共享密码、HTTP Basic 和旧 SQLite 会话不能绕过成员身份继续访问；日常管理脚本需单独明确认证方式，迁移/备份 CLI 保留受控服务端操作入口。

| 标识 | 含义与规则 |
|---|---|
| user_id | 不变的成员 ID；昵称改名不会改变画布、任务和记录归属 |
| 登录会话 | 一次登录的服务端会话，Cookie 只携带不可猜测的凭证；支持退出、到期、停用成员及重置密码后撤销 |
| 编辑会话 | 某一画布标签页的编辑实例，绑定成员和登录会话；不同标签页/设备不能因同账号而共用写权限 |
| 锁代次 | 每次新领取或接管递增的 fencing generation；续租不变，释放不能重置，旧代次永远不能重新生效 |

昵称和头像由成员资料统一管理。昵称允许重复，必要时附成员短编号；不以昵称、IP、前端自报 user_id 或 client_id 鉴权。公开锁状态不返回登录凭证、内部登录会话标识或可用于续租/释放的私密凭证。

下表为内置空间角色模板；自定义角色按固定权限点配置，不以角色名称判定权限。平台角色与空间角色分开，空间管理员不会自动获得平台管理权限。

| 操作 | 查看者 | 编辑者 | 空间管理员 |
|---|---|---|---|
| 查看共享画布/素材、查看在线成员、导出 | 允许 | 允许 | 允许 |
| 新建画布、上传素材、修改共享目录 | 禁止 | 允许 | 允许 |
| 编辑/重命名/恢复/删除已有画布 | 禁止 | 取得有效编辑租约后允许 | 正常持锁或明确接管后允许 |
| 发起生成及付费操作 | 禁止 | 有成员权限；画布关联操作还需有效编辑租约 | 同编辑者规则 |
| 管理本空间成员/角色、强制接管 | 禁止 | 禁止 | 在可授予权限范围内允许，敏感变更留审计记录 |
| 平台成员管理、供应商配置、平台维护 | 需另授平台权限 | 需另授平台权限 | 需另授平台权限 |

同一空间内的共享画布与素材不按创建人隔离，跨空间访问必须独立校验成员资格和权限。对话仍保留按身份访问语义，升级为服务端成员身份并绑定所属空间；不因迁移把个人对话自动公开。成员禁用不删除其共享作品和历史费用。

## 4. 编辑租约与保存协议

### 数据模型草案

表名为建议，实施时采用追加 migration，不改写已应用的 001–003。

| 数据 | 主要字段或约束 |
|---|---|
| members / workspace_members | user_id、账号标识、昵称、头像、密码哈希、状态；workspace_id + user_id 唯一；角色定义及授予关系独立保存，支持多空间、多角色 |
| member_sessions | 会话凭证哈希、user_id、到期/撤销状态；服务端管理，不存浏览器上报的可信身份 |
| canvas_edit_leases | workspace_id + canvas_id 唯一；user_id、内部登录会话关联、编辑会话凭证哈希、generation、acquired_at、renewed_at、expires_at |
| canvas_transfer_requests | 申请人、目标编辑会话、申请时锁代次、状态、到期时间；仅当前代次的有效申请可以被批准 |
| collaboration_events | 操作者、画布、事件类型、前后锁代次、结果、原因、服务端时间；不记密码、会话凭证或完整画布正文 |
| 现有画布、任务、可变记录 | 增加 created_by / updated_by / requested_by 等必要关联；历史未知值允许空，不能伪造过去的成员 |

建议心跳 10 秒、租约有效期 60 秒，均可配置。是否到期由数据库时间判断；客户端倒计时仅供展示。领取、续租、释放都使用短事务，编辑期间不长期占用数据库事务或行锁。

### 领取与保存

1. 打开画布只订阅查看状态；点击“开始编辑”后校验登录会话、成员状态、空间资格、权限点和有效维护状态。
2. 领取使用唯一约束配合原子条件更新/插入，覆盖首次不存在租约行时的竞争；不能先查询“无锁”再无条件插入。
3. 成功后返回本编辑会话所需凭证和当前锁代次；其他成员只收到经过裁剪的持有者信息。
4. 保存必须携带编辑会话凭证、generation、base_revision。服务端在同一短事务中锁定并检查空间资格、权限/会话、维护状态、租约和画布版本，再更新文档、引用索引及修改人。
5. 领取、接管、撤销、保存采用统一行锁顺序，防止“先检查、后写入”间隙被接管或停用。续租/释放必须匹配当前绑定及 generation；旧会话不能释放新会话的锁。
6. 现有 revision 保留为第二道并发检查；返回稳定错误码区分未登录、无权限、他人持锁、租约失效和版本冲突，前端据此进入查看或草稿恢复流程。

写入清单必须逐项核对：整体保存、元数据/目录归属、触碰更新时间、回收站/恢复/永久删除、备份恢复、导入覆盖、关联生成请求、费用日志追加及任何间接写入路径。画布新建原子建立初始归属，返回后再领取编辑租约；创建副本不需要原画布写锁，但要求成员具备新建权限。独立素材/目录操作按角色校验，不强行套用无关画布锁。

普通 API 不接受客户端声明“我是系统任务”绕过租约。旧客户端缺少新协议时明确要求刷新升级，不能静默降级为无锁写入。

### 接手与后台结果

- 本人另一个窗口：明确点击“在此窗口接管”，产生新代次，旧窗口失去写权限。
- 他人正在编辑：提出接手申请，持有者可“保存并交接”或拒绝；申请到期或锁代次变化后失效。只批准指定申请，不通过先释放再抢锁完成交接。
- 管理员强制接管：再次确认、填写原因、生成审计事件；保留数据库中的最新已提交版本，不能声称已保存旧窗口尚未上传的内容。
- 正常结束编辑/交接时先确认最终保存，必要备份记录与指定 revision 对应，随后原子释放/转移并记审计。失败不能显示“已保存并交接”，不得在未授权释放请求到达时反复生成备份。
- 释放画布锁不取消已提交的生成任务。排队但尚未向供应商提交的任务在执行前复验成员是否仍有生成权限；成员停用/降权后暂停并明确状态，不继续发起新的付费提交。
- 已提交的任务由服务端继续查询、落库结果并保留费用。结果先独立持久化；普通客户端加入画布须持有效编辑租约。后台自动回填仅限有持久任务授权的内部路径，并核对当前画布版本、目标节点和任务关联；节点已删除/更换或发生冲突时保留待加入结果，不覆盖旧快照。

## 5. 两种画布的交互和在线状态

| 状态 | 展示与可用操作 |
|---|---|
| 查看，无人编辑 | “开始编辑”；浏览、缩放、预览、导出可用 |
| 自己编辑中 | “你正在编辑 · 已保存/保存中”；提供“结束编辑” |
| 他人编辑中 | “小王正在编辑”；可以查看并申请接手，不使用遮挡整张画布的等待层 |
| 同账号另一个窗口编辑 | “你已在另一个窗口编辑”；提供“在此窗口接管” |
| 连接或续租异常 | “连接中断，已暂停编辑；未保存内容已保留”；暂停写入、保留草稿，不误报已保存 |
| 租约被接管/会话失效 | 切换只读并提示原因；提供草稿恢复入口，重新验证权限后才能共享保存 |

草稿按成员、空间、画布和编辑会话隔离，记录 base_revision，使用 IndexedDB 等本地持久存储。切换账号或空间不读取或展示其他成员/空间草稿；个人端清理策略需明确。恢复连接先确认登录、锁代次和最新 revision：完全匹配才允许重试保存；有差异则让用户选择复制为新画布、导出草稿或人工合并，不自动覆盖。

WebSocket 传送编辑状态/接手事件，数据库查询是权威来源，轮询用于断线兜底。短暂断开不立即释放租约；关闭页面的 beacon 只是尽力释放。后台标签页或设备休眠导致无法续租时，同样暂停写入，不假定浏览器计时器一直可靠。

在线名单区分编辑者和查看者，按成员去重计人数；设备/标签页只在需要区分本人会话时展示。订阅和广播均检查成员权限及所属工作区/画布，断线移出在线名单不等于编辑锁立即失效。消息包含锁代次或状态版本，旧事件不能覆盖新状态。

IP 仅供管理员排障，日志中的来源地址只信任明确配置的反向代理链，不直接信任任意 X-Forwarded-For。普通锁 API、错误体、WebSocket 消息和悬浮提示不返回 IP。

当前在线名单实现与本地证据见[在线成员验收](member-presence-local.md)。名单跨进程可见与画布状态订阅分别验收；当前快照订阅、查看页同步及故障边界见[画布订阅验收](canvas-subscriptions-local.md)。

## 6. 迁移、启用与回退

1. 保留当前存储验收基线，新增 migration 在隔离 PostgreSQL schema 中验证；先备份开发库再应用已验收变更。
2. 初始化管理员及少量测试成员；旧共享入口仅用于启用前的旧模式，线上成员模式启用后撤销旧会话并要求重新登录，不双轨接受旧身份。
3. 浏览器旧昵称只作为用户确认昵称的建议，不导入为账号或可信成员身份。
4. 历史 IP、owner 文本、自报 ID 保留在历史元数据；只有经管理员核对的映射才能关联新成员。旧对话需明确归属映射；未映射的对话保留并列入迁移报告，普通成员不可按旧 X-User-ID 直接读取。
5. 旧内存锁不迁移为新有效租约。停写并通知保存后切换；所有页面刷新协议，重新领取编辑资格。
6. 画布、节点、任务和素材原 ID、TOS key/version、原账本金额/日志/去重指纹保持原值；成员关联通过新增字段或独立关系补充。
7. 备份恢复后保留成员、角色和审计历史，但撤销恢复出的登录会话、编辑凭证、租约及待处理交接，要求重新登录/领取。防止恢复旧数据库复活旧凭证与旧锁代次。
8. 回退先停写、保存升级后的数据与草稿恢复信息，使用与数据库兼容的代码版本；不得在公网重新启用旧共享认证和无锁写入来“临时兼容”。

## 7. 画布协作阶段与提交

统一顺序为 M1+C1 → M2 → C2 → C3 → M3 → M4，详见[管理平台计划](management-platform-upgrade-plan.md)。C1 与 M1 合并实施身份、空间及权限底座，避免重复建设；维护策略在底座阶段定义。

| 阶段 | 工作内容 | 完成门槛 | 当前状态 |
|---|---|---|---|
| C1：成员身份（合并 M1） | 追加成员/会话、空间及自定义角色关系；管理员初始化与成员激活；空间分配；统一身份及权限点；对话归属；旧身份切换规则 | 多成员登录、重名/改名、退出/停用/降权、伪造身份、旧 Basic/会话禁用测试通过；共享资源按空间及权限点访问，跨空间越权被拒 | 进行中：服务基础完成，业务接入待完成 |
| C2：数据库编辑租约 | 编辑凭证及锁代次、领取/续租/释放；统一写入校验；并发/过期/撤销；备份及任务回填边界；后端接手与审计协议 | 多连接和跨进程争抢只有一个持有者；旧代次和绕过接口请求全部被拒；保存/接管/撤销竞争不丢更新 | 进行中：后端租约、写入检查与指定交接已实现，完整联调待完成 |
| C3：双画布协作体验 | 共用协作客户端；查看/编辑状态；本人接管、申请交接、管理员接管；草稿及断线恢复；空间切换；在线名单；完整迁移/恢复演练 | 两成员、同账号双标签页/双设备场景通过；两种画布实际浏览器验收及全量回归通过 | 进行中：指定交接、强制接管、草稿恢复/清理/原子副本和嵌入页保存刷新已接入；跨进程在线名单、状态订阅和清洁查看页同步已验收；后台结果加入、完整故障及剩余浏览器联调待完成 |

每阶段形成独立 Git 提交，记录实施内容、对应 migration、测试和已知边界；C2 的协议在 C3 配套前不对日常用户启用。具体工期在 C1 的写入路径与身份数据盘点完成后评估，不把当前功能基线的通过数当作新功能的验收结果。

| 编号 | 必须验证的场景 | 通过标准 |
|---|---|---|
| ID-1 | 不同成员同公网 IP；同成员换网络/改昵称；两成员重名 | 身份和权限不随 IP/昵称漂移，显示可区分 |
| ID-2 | 伪造 username、X-User-ID、client_id、工作区及画布 ID | 无法冒充、续租、释放、读取他人对话或越权写入 |
| SP-1 | 同成员跨空间不同角色、猜测另一空间资源 ID、移出空间 | API/实时订阅均拒绝越权；失去成员资格后旧租约不能保存，缓存和草稿不串空间 |
| ID-3 | 退出、过期、停用、降权与进行中的保存/续租竞争 | 服务端按事务顺序判定，撤销生效后不再接受新操作；实时连接同步失效 |
| LK-1 | 两成员并发首次领取、过期后并发接管、多连接/多进程争抢 | 每张画布最多一个有效租约，代次持续递增 |
| LK-2 | 同账号两标签页/两设备；复制标签页；旧释放请求重放 | 只有当前编辑会话能写，旧会话不能释放新锁 |
| LK-3 | 断网、休眠、WebSocket 抖动、浏览器关闭、服务重启 | 租约按约定续租/到期；客户端暂停写入并保留草稿，不永久锁死 |
| LK-4 | 锁过期但 revision 未变；持锁但 revision 已变；接管与保存并发 | 两种校验都不可绕过，旧快照不能覆盖新状态 |
| WR-1 | 整体保存、元数据、恢复/删除、导入覆盖、生成及其他旁路 | 每条实际写入路径均有角色及所需租约校验，错误响应一致 |
| TR-1 | 批准交接时第三人抢锁、申请到期、旧批准消息、重复点击 | 只转移给有效指定申请；旧代次申请拒绝；备份/审计不重复 |
| TR-2 | 管理员接管有未保存内容的画布 | 原编辑者变只读，草稿可恢复，审计记录原因，不谎报未上传内容已保存 |
| TK-1 | 任务生成期间交接/删节点/停用成员 | 已付费结果及费用不丢；无新盲目付费请求；不覆盖交接后的画布 |
| UI-1 | classic/smart 各执行完整查看→编辑→保存→交接→恢复流程 | 成员展示一致，无 IP 泄露；状态真实，查看功能可用 |
| MG-1 | 旧昵称、owner、IP、对话映射及未知归属 | 不自动认领历史身份；未映射数据完整保留并可核对 |
| BK-1 | 恢复到新数据库/对象目录 | 成员及角色、画布、媒体、费用、审计可用；旧认证和编辑凭证全部失效 |
