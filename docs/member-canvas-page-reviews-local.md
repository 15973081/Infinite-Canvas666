# 维护页面报告人工核对：本地实现与验收

第十六批补齐独立管理平台的页面报告核对。追加 migration 011，为已有报告分配独立 UUID，并保存被核对序号、处理人、时间、结果和说明。开发库仍未应用 004–011；本批未启用真实成员模式。

## 行为与边界

维护中心提供待核对和已核对列表，按当前空间或全平台范围查询，支持分页。列表展示画布、空间、成员及最后报告状态，不暴露登录会话、页面凭证或草稿正文。只有管理站点会话并具有对应 maintenance.space / maintenance.platform 权限才能读取和处理；工作台会话不能调用管理服务。

只有失联或关闭时未保存的报告可核对。管理员必须明确选择“已向成员确认保存”“已确认草稿导出”或“成员确认无需保留”，并填写说明；选项默认空白。核对不修改 dirty、closed、seen_at、画布 revision 或租约，也不保存、导出或删除成员草稿。原统计继续显示失联/关闭时未保存数量，另列待核对和当前报告已核对数量。

提交携带期望报告序号；事务取得报告行锁后重新检查新鲜度和序号。在线、已正常关闭、已核对或序号变化的报告拒绝处理。核对记录和 maintenance.page.review 审计同一事务提交，失败一起回滚；并发重复提交只产生一条审计。新的更大序号不受旧核对覆盖，再次失联时重新列入待办；此前说明仍可查看，完整历史留在操作审计。

列表返回后还核对页面、成员、范围和请求顺序，退出、切换范围或较新列表请求后，不再弹出迟到的旧结果。表单冲突提示显示在弹窗内部，保留用户填写内容。

人工核对只确认操作人员对某次报告的处置结论，不证明全部浏览器已保存。未上报页面、付费任务、备份及恢复检查仍需独立处理；database_stop_ready 保持 false。报告保留与归档策略、完整排空及部署恢复门槛继续实施。
