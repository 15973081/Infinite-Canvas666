## 行为与边界

提交前使用实际保存投影捕获源节点、目标节点及上游输入，包含当前尚未保存的提示词和设置；投影与保存一致地剔除图片上的旧生成元数据、临时媒体地址并规范空 images。等待保存完成后携带 canvas_target，提交回执必须与当前 operation 一致。请求使用 CanvasApi，经过 MemberCanvasEdit 附加当前画布编辑协议与凭据。

等待记录以不可枚举属性持有本页 operation；保存 JSON 不包含该对象，跨刷新记录不能获得原页面的自动回填权。轮询缓存保存完整任务，每个调用方独立核对 task ID、编辑代次及不可变回执。成功写入、失败清理、队列归档均在输入与身份复验后执行。同批结果和自身归档推进预期输入；修改提示词、模型、替换节点或交接时保留独立结果，避免旧回调覆盖新内容。

主入口捕获运行设置，异步返回后不再依赖可能被切换的全局设置。结束时只有仍属于本次的选择、提示词和设置才恢复界面；串联和循环也移除迟到的全局设置覆盖。延期结果不执行循环预览收尾。

## 浏览器发现的实际问题

1. 原智能提交直接 fetch，没有新版编辑凭据，真实按钮返回 canvas_protocol_required。改走统一 CanvasApi；测试加载真实 CanvasApi，并断言提交和轮询经过编辑凭据 transport。
2. resultMediaUrls 只遍历对象字段，而图片调用传入 result.images 数组，导致真实任务成功后提示没有返回图片。补齐顶层数组和字符串解析，保留既有去重和媒体尺寸；测试使用真实解析器。
3. 视频沿用图片 count=2，实际仅创建一个任务，完成后 pending=1、计时继续。视频预期数固定为 1，队列和恢复以实际 pendingTasks 数量为准；验证完成后 pending=0、运行关闭、完成时间已保存。
