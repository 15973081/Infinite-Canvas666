# 私有附件独立删除账本

适用于 PostgreSQL 成员模式的私有对话附件及预览、对话删除、Skill 原包彻底删除和账号注销。账本独立于会被还原的数据库，用于避免恢复旧备份后重新开放已删除内容或已注销账号。

## 部署

在 API 与所有 cloud worker 实例上配置相同的 `DELETION_LEDGER_ROOT`，指向独立、持久、只允许服务账号访问的共享目录。不能放在对象目录、临时目录、代码发布目录或随数据库备份一起回滚的目录中。TOS 部署必须显式配置；本地 filesystem 模拟未设置时使用对象目录旁、按对象根路径区分的目录。

账本包含不可覆盖的 `.ledger-id`、哈希命名的 JSON 删除意图和附件拒绝访问索引。JSON 保存成员/对话/Skill 标识，以及附件准确对象键和版本，不保存正文、原文件名或上游模型输入；未知字段会被拒绝。保持账本长期连续；不能为恢复旧备份而用旧账本覆盖当前账本，也不能随意删除身份文件。已有记录但身份丢失时，服务拒绝创建新的账本身份。

删除任务在数据库中排队并停止附件访问，然后持久化账本，再删除对象版本。账本写入或对象删除失败，任务进入退避重试；即使数据库回退，当前账本仍记录已删除意图。容量在物理清理及数据库完成后释放。

## 恢复

`tools/cloud_restore.py` 仅支持经过校验的 filesystem 本地备份包，目标必须是空数据库和新目录。备份清单记录账本身份；恢复必须能访问相同身份的当前账本。目录迁移时用 `--deletion-ledger` 指定迁移后的当前目录，身份必须一致。

恢复工具在写目标前检查账本，跳过已删除的对象版本，复制后再次读取账本并清理新增删除对象，在数据库还原的同一事务中校验所有者和对象身份、重放附件/对话/Skill 原包删除及注销、记录审计并撤销旧会话。Skill 安装及库快照中相应条目也会移除；其他对话已保存的独立 Skill 引用快照按对话归属保留。完成后仍保持恢复隔离状态，供运维检查。`tools/cloud_storage.py restore-objects` 同样跳过账本中的已删对象。

账本缺失、身份不匹配、记录损坏或对象身份不一致会中止恢复。没有账本描述的旧备份不能通过本流程自动开放；需先完成可核验的运维迁移，不能创建空账本冒充删除历史。TOS 原生对象版本的全库恢复不在当前支持范围内。

本功能不会修改既有备份包、撤回已下载文件或删除供应商已收到的内容。备份字节的保留期、访问控制、到期销毁，以及账本自身的持久化和灾备仍需要单独配置。

## 验证

真实 PostgreSQL 测试验证：删除前备份，之后彻底删除，再恢复旧备份；原对象不复制、数据库维持已删、清理任务完成、审计可追溯、无关对象仍保留。另验证离线对象恢复、账本缺失/身份错误提前停止、不可替换删除意图和身份丢失保护。测试运行器强制使用独立临时账本，避免触及部署配置目录。
