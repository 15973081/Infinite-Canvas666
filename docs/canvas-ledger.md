# 画布费用流水与日志恢复

## 存储与迁移

费用明细独立保存在 `data/canvas_ledger.sqlite3`，按 `canvas_id` 归属画布。可通过 `CANVAS_LEDGER_DB_PATH` 改变路径。原画布 `data/canvases/<id>.json` 中的 `logs` 继续保留，作为旧客户端兼容数据，仍最多保留 5,000 条；独立流水不受此上限影响。

打开、保存画布或读取费用时，将当前 `logs` 增量导入独立库。按日志 ID、本站任务 ID、平台与上游任务 ID 去重；没有 ID 的旧日志使用稳定内容指纹。不会因某次保存的日志更少而删除独立流水。导入记录来源、原始日志、有效费用快照以及冲突候选，迁移可以重复执行。

新 API 图片和视频任务提交时关联画布并保存价格快照，任务状态及结果保存在 `data/canvas_tasks.sqlite3`。完成后后台直接记账，浏览器关闭不影响已完成任务的流水写入；暂时写入失败的流水在读取费用时从任务库补齐。前端回报携带相同任务 ID，避免再次计费。其他生成路径在生成日志时立即请求写入独立库，待写入或失败状态会在日志界面提示。

## 日志恢复

普通画布、智能画布的生成日志和费用仪表盘均提供“日志恢复”。

1. 读取当前画布的 `logs`、`data/canvases/backups/<id>/*.json` 中的 `logs`，以及有明确画布/任务 ID 关联的任务记录。
2. 预览新增、补全、重复、冲突和无效记录数量，展示补录前后的费用与总条数。预览事务回滚，不修改画布或流水。
3. 用户点击“确认补录”后，在一个事务中补齐流水。预览绑定输入内容、价格配置和流水版本；期间有变化时要求重新预览。

保留已有金额，冲突不会静默改价。仅缺少金额的记录可以补入有依据的费用。恢复不会回滚布局，不会重新生成内容，也不会将全部历史重新塞回画布 JSON。已被截断且所有备份、关联任务均未保留的记录无法恢复；界面会说明覆盖范围。备份恢复不会借助提示词相似性推断所属画布。

## 计费与界面

- 已有费用快照保持原金额、币种和单价；模型、规格、时长、`usage`、`video_info` 随日志保存。缺失费用只按现有有效历史价格回算并标记预估，缺少证据则标为待核算。
- 火山视频沿用 Token 计费结果；上游成功但下载失败时仍保留费用。旧版已定价的按秒历史快照保留，缺少 Token 的火山新记录不猜测秒数金额。
- 金额以整数微元存储和汇总，不将各笔显示到分的数字再相加。其他币种单独汇总，不折算进人民币。超出前端安全整数范围时明确报错。
- 明细默认每页 50 条，费用合计覆盖所选日期的全部流水；工具栏费用保持整个画布总额。日期按浏览器本地时区，包含结束当天。
- 用户脚本 `userscripts/canvas-legacy-cost-filter.user.js` 2.1.0 通过 `CanvasLedger.readAll` 分页读取完整流水，保持右侧旧秒价口径，单独核算，不覆盖左侧原始费用。

## 接口

- `GET /api/canvases/{id}/ledger`：`page`、`page_size`（最多 200）、`from_ms`（含）、`to_ms`（不含）；返回明细、全部筛选汇总及 `revision`。
- 跨页读取传 `expected_revision`，版本变化返回 409，调用方从第一页重新读取，避免混用两个版本。
- `POST /api/canvases/{id}/ledger/entries`：`{"logs": [...]}`，最多 5,000 条，幂等追加/补全。
- `POST .../recovery/preview`：返回恢复报告及 `preview_token`。
- `POST .../recovery/apply`：提交 `{"preview_token":"..."}` 执行已预览内容。

部署需重启后端并刷新画布页面；油猴脚本需要替换为 2.1.0。备份服务应包含画布目录、任务数据库和流水数据库；仅导出画布 JSON 不等于备份全部流水。运行中备份 SQLite 应使用 SQLite backup API，或停服后复制，避免遗漏 WAL 中的数据。删除画布不会自动清除费用流水。

`python/python.exe tests/test_canvas_ledger.py` 和 `node --test tests/test_canvas_ledger.cjs tests/test_canvas_legacy_cost_userscript.cjs` 使用临时数据库和模拟网络，覆盖 5,101 条全量汇总、保存回退、任务去重、价格快照、恢复预览/重复执行/版本冲突、币种和整数精度、跨页一致性、前端重试与旧插件兼容。
