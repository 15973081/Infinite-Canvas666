# Classic 画布管理列表：计算与呈现分离（2026-10-05）

通信与模块边界计划第 4 轮，基线 `198982b`。范围仅 Classic 管理列表、计数和文件夹树的展示计算及搜索入口；不整理全局选择、文档、保存、历史或任务。

## 计算与操作入口

原入口在列表、文件夹树和控制栏反复筛选，文件夹逐个扫描全部画布计数。卡片绘制同时判断类型、图标回退、颜色、置顶、当前画布和封面样式。

`canvas-gate-model.js` 将这些计算收归固定功能模型：显式输入画布列表、回收站、文件夹、当前文件夹、查询、模式和当前画布 ID。无 DOM、存储、网络或定时器依赖，可以直接在 Node 中测试。

- `build()` 一次派生列表、卡片展示字段、空态、文件夹计数和分组；冻结其自有数组与字段。保留原文档/文件夹记录引用，不冻结业务记录或复制成另一个状态所有者。
- 查询规范化、置顶优先排序、名称数字比较、时间兜底、文件夹查询/深度也在模型内。旧函数名是显式传入原所有者数据的薄委托。
- 渲染只读取模型，控制栏、递归文件夹树和卡片共用一次结果。文件夹计数按一次扫描派生，不再为每个文件夹重新筛选画布。
- `searchCanvases()` 完成更新查询、原元信息关闭和呈现；`clearCanvasSearch()` 完成清空、呈现及按入口需要恢复焦点。原 input/Escape/清空按钮不再组合字段赋值与刷新。
- 原排序与切文件夹命令仍维护关联状态、排序记忆和刷新顺序，每次操作复用一份模型，保留原动画之前的文件夹呈现时机。

列表数据、当前画布和 UI 选择继续由 Classic 入口原流程持有。文件夹合法性处理仍在既有数据更新命令内，模型或渲染不修正选择。读取计算与元信息写入、移动、打开、重命名、回收站操作保持分离。

## 行为保持

保留 NFKC 与中文小写搜索、当前文件夹筛选、回收站忽略当前文件夹、实时文件夹计数不受搜索/回收站影响、置顶优先、名称/时间排序、空态优先级，以及 Smart 图标回退、封面样式和删除确认显示。

原列表卡片/文件夹 DOM 重建方式、200ms 高度与 180ms 淡入动画、菜单和操作控件不换成新组件。工作区局部更新与 DOM 复用保留；正常关闭画布仍按原 `setCanvasMode(false)` 清空工作区，不为测试保留节点改变这个规则。

元信息、移动、重命名、打开和回收站的 API、权限与保存时机不改。读取模型和本地列表搜索不写文档；业务写操作继续由原具体命令完成，不能据此推导所有列表操作都不保存。
