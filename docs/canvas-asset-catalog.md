# 画布资产整理

PostgreSQL 模式新增重命名、分类、标签、当前空间画布节点引用查询，以及批量整理、移入回收站和恢复。编辑权限为 asset.manage，读取需要 asset.read 与 canvas.read。

整理信息按 workspace_id + asset_key 保存；云素材稳定 URL 与历史别名归一至同一 asset ID，外链按完整 URL 哈希。改名不改对象 key 或画布节点字段。

回收站是资产目录层的可恢复归档：隐藏素材列表条目、保留原文件和画布引用；恢复重新显示条目。不会阻断已有生成任务、下载或画布显示，不会立即释放 TOS 存储。尚不包含永久删除或对象垃圾回收。引用查询覆盖当前空间的画布节点（包括画布回收站），不代表历史任务、备份等所有引用。

批量修改原子执行，最多 200 个唯一素材，并校验每个素材的版本。整批有冲突则回滚。分类和标签可通过资产搜索框查询。

本次只迁移当前本地运行的 PostgreSQL schema，未写入远端空数据库。未来部署需要执行对应结构迁移。

验证：4 个单元测试；隔离 PostgreSQL 事务覆盖多节点引用、跨画布元数据、回收/恢复、版本冲突、跨空间隔离、画布节点不变，事务结束回滚测试数据。

## 独立画布素材分组（020）

PostgreSQL 模式新增 canvas_asset_groups，以空间和画布 ID 保存独立素材清单，不外键绑定画布。迁移从现存画布记录补录，包含已回收及 purged_at 已标记的画布。每次画布保存，在同一事务内合并素材清单和更新来源名称、状态；移除节点不会撤销已登记的素材成员。

资产页提供使用中的画布、已删除画布、全部画布筛选，后者包括已回收和已清理来源。素材回收站与来源状态筛选可组合使用。素材的编辑、回收、恢复仍按空间和素材身份生效，不改动原文件。

仅能补录数据库现存记录中可识别的素材；迁移前已从节点移除且没有其他记录的素材，或未曾保存进画布的任务输出，不保证自动补齐。当前不扫描 TOS 桶，也不物理删除对象。JSON 文件存储模式没有独立持久分组，本次面向 PostgreSQL 云模式。

测试：tests/test_canvas_asset_groups.py 覆盖分组合并、来源筛选；设置 CANVAS_ASSET_GROUP_INTEGRATION=1 后，在 canvas_delivery_ 本地测试数据库中执行完整保存、移除节点、回收、清理、素材编辑与恢复、跨空间隔离和源记录移除流程，全部测试数据事务回滚。
