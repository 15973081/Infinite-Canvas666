# Smart 视频截取：面板会话与提交任务边界

日期：2026-10-04。普通预览阶段已单独提交为 `f486c7e`。本记录承接该提交，原始 `canvas-global-state-inventory.json` 不改动。

## 范围与所有权

`createSmartVideoTrimPanel()` 位于 Smart results，唯一持有截取面板的开关、起止时间、时长、试听、忙碌状态和专属 DOM。入口只初始化 `smartVideoTrimPanel` 并绑定一次控件。

入口中的 `videoTrimState` 与最小时长常量移出；原 `sourceUrl` 不再作为会话的第二份目标信息保存。应用时从编辑器获取有效来源，提交后才记录请求事实。忙碌状态从当前面板所属请求回执派生，不保留第二个可变标记。面板的冻结 `state` 提供时间、开关、试听、忙碌、打开等待、暂停及提交任务数量等标量。

| 范围 | 所有者与协作 |
| --- | --- |
| 截取会话、10 个 ID 控件引用及局部按钮监听 | `smartVideoTrimPanel` 私有闭包 |
| 播放器、当前媒体、播放状态 | 原 `smartPreviewGestures`；截取读取冻结 `videoState()`，调用暂停、定位、播放和播放器事件订阅入口 |
| 图片／视频目标、分组索引、模式 | 原 `smartImageEditor`；截取使用目标查询和编辑器提供的目标／模式回调保护，不复制目标 |
| 已提交请求 | 提交时固定的画布 ID、源 URL、名称、起止时间、尺寸及结果位置；请求独立于面板清理继续完成 |
| 节点、选择、撤销和保存 | 原写回流程；不改画布撤销或保存核心 |

未更改截取 API、服务端 FFmpeg 算法、0.1 秒最小时长、时间格式、范围约束、结果元数据、结果位置算法或普通预览／全景算法。没有引入通用控制器、React 或其他框架。

## 操作入口

旧函数名保留为薄委托：开关、关闭／重置、范围输入、时间输入提交、设为当前、试听和提交截取。所有关联状态和 UI 刷新由所属命令完成；忙碌时拒绝再次提交或修改范围。

专属控件由面板显式注册监听，替换原 HTML 内联处理器；节点结构、类名、显示内容和脚本加载顺序不变。重复 `bind()` 先解绑上一次专属控件监听。播放器的 `timeupdate`、`ended` 与元数据／定位等待也有对应的解绑记录，不再依赖播放器 `dataset.trimEventsBound` 标记。

呈现函数读取会话，不修正时间或选择。无效目标禁止时间修改、试听和提交，但关闭仍可执行。

## 面板与任务生命周期

关闭、重开、切视频、离开普通预览及切换画布时，面板重置会话代次，停止试听，取消自己的等待和定时器，并解绑播放监听。迟到元数据不能打开旧面板；迟到定位不能开始播放新视频；旧播放失败不能修改重开的试听状态。

缓存页面离开暂停自身监听／试听与等待。返回由编辑器恢复目标，再恢复面板监听与当前范围；永久离开销毁控件监听及 DOM 引用。普通预览和共享工作区的其他监听不由截取面板清理。

已提交请求不因关闭、暂停或销毁面板而取消。回执只使用提交时固定的参数和尺寸，不读取清空后的范围或另一个视频的尺寸。每项请求独立记录其忙碌归属，旧回执不能清除重开会话中新请求的忙碌状态。

成功回执在同一画布中仍按原流程添加新视频节点、创建一条撤销记录并调度保存。原流程包括 `createImageNodeAt()` 内的一次保存调度及结果处理后的另一次调度，共两次，由原保存机制合并；本轮未为减少调度数量修改保存行为。提交会话仍有效且面板仍打开时，继续切换到新片段；会话已失效时不重开已关闭的编辑器或覆盖用户新开的预览。

画布已变化时，已生成文件保留，回执返回文件结果，但不把前一画布的节点插入当前画布。本轮不增加后台保存旧画布、跨页面任务恢复或服务端任务版本协议。

## 保留范围与风险

全景、视频帧导出、音频预览、画布撤销、生成任务与保存核心保持原所有者，未继续扩大封装。图片／视频目标和播放器也没有迁入截取面板。

本轮未做真实截取服务端联调、长视频／大文件性能基准或跨浏览器验收。已提交任务跨画布或跨页面的自动恢复不在本阶段；切换画布后的文件保留，但不自动回写离开的画布。词库响应竞争及服务端版本一致性继续独立记录。
