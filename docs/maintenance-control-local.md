# 平台与空间维护：当前实现和验收

本批在独立管理站点新增维护中心，并把维护规则接入成员工作台、上传和持久任务。开发库尚未应用 migration 004–007；全部验证使用本地隔离测试 schema 和对象模拟，未调用真实付费模型。整体升级和 M3 完整验收仍未完成。

## 已实现的行为

`maintenance_controls` 持久保存平台/空间状态、公告、内部原因、计划时间、上传收尾截止、版本和操作者。支持 normal、scheduled、draining、read_only、offline、recovering；状态变化校验 expected_version，并记录管理审计。空间维护管理员不能修改平台维护或读取平台操作者的内部原因。

- normal 可以安排计划或开始排空；计划可取消；排空可转为只读、暂停访问或恢复检查。
- 暂停访问只能先进入恢复检查；恢复检查转为正常开放要求明确确认，不能因进程启动或浏览器重开自动解除。
- 每次请求/数据库操作按更严格的平台和空间限制判定。空间恢复不会解除平台维护。
- 成员工作台的已迁移 HTTP 入口在事务开始时再次复验维护状态。只读允许查看/预览/导出，排空阻止新增共享写入；暂停访问和恢复检查阻止业务读取。已登录成员仍可读取最小维护状态、账号及空间选择信息。
- WebSocket 状态流携带持久版本和公告；暂停访问时不返回任务列表/计数。正式工作台维护页和双画布交互仍待 C3 接入。
- 计划按 PostgreSQL 时间判定。即使调度进程暂时停止，到时后的请求和任务领取也受限制；后台协调器将到期计划写成 draining，多个协调器只生成一次状态变化与审计。
- 业务和管理进程均可运行轻量计划协调器；管理进程不启动生成消费者。业务/worker 持久心跳供后台观察，超过 35 秒未更新显示无有效在线心跳，不以网页仍能打开推断业务在线。

## 上传、任务和付费边界

新的上传会话在排空后拒绝。排空前创建的分片上传可以在既定宽限内续签、传片、确认及完成，截止由数据库判定；修改公告不延长原有宽限。本地预签名 PUT 在接收及落库时都检查维护状态，不能用早先取得的签名绕过截止时间。

TOS 已签发凭证在有效期内仍可能直接写入 staging；服务端的完成/发布接口继续检查维护规则。已发出的素材 GET 能力也不因维护或撤权立即失效，不把维护公告当作已撤销外部签名的证明。

排队但未提交的任务在维护时不领取；刚领取后才开始维护的任务会恢复为 queued 等待。已知上游任务和结果发布可以继续处理，避免已付费结果丢失。

生成适配器的每次付费 POST 经 `submission.paid_post` 复验执行租约、可信发起成员、空间权限、供应商账号绑定和维护状态，并记入 `task_submissions`。**短事务中接受提交是该次调用的准入边界**：之后发生的维护/撤权不会取消这个已准入的在途请求，但会阻止后续批次项、回退或新调用再次准入。网络不明确结果记 uncertain，不据此盲目重发；已有持久任务继续执行原有恢复协议。

批量生图等待所有并发项结束，保留成功部分后独立发布素材、历史和费用，结果标记 partial 及未完成数量。成功图片数与最初请求数分开保存；失败项不会让已成功图片被整批丢弃，也不会将请求的全部数量当作已完成数量计价。
