# 平台与空间维护：当前实现和验收

独立管理站点已接入维护中心，维护规则覆盖首批成员工作台、上传、持久任务及画布租约。开发库尚未应用 migration 004–010；全部验证使用本地隔离测试 schema 和对象模拟，未调用真实付费模型。整体升级和 M3 完整验收仍未完成。

## 已实现的行为

`maintenance_controls` 持久保存平台/空间状态、公告、内部原因、计划时间、编辑和上传收尾截止、版本和操作者。支持 normal、scheduled、draining、read_only、offline、recovering；状态变化校验 expected_version，并记录管理审计。空间维护管理员不能修改平台维护或读取平台操作者的内部原因。

- normal 可以安排计划或开始排空；计划可取消；排空可转为只读、暂停访问或恢复检查。
- 暂停访问只能先进入恢复检查；恢复检查转为正常开放要求明确确认，不能因进程启动或浏览器重开自动解除。
- 每次请求/数据库操作按更严格的平台和空间限制判定。空间恢复不会解除平台维护。
- 成员工作台的已迁移 HTTP 入口在事务开始时再次复验维护状态。只读允许查看/预览/导出，排空阻止新增共享写入；暂停访问和恢复检查阻止业务读取。已登录成员仍可读取最小维护状态、账号及空间选择信息。
- WebSocket 状态流携带持久版本和公告；暂停访问时不返回任务列表/计数。工作台维护提示和双画布编辑限制已分批接入，完整故障及排空联调仍待完成。
- 计划按 PostgreSQL 时间判定。即使调度进程暂时停止，到时后的请求和任务领取也受限制；后台协调器将到期计划写成 draining，多个协调器只生成一次状态变化与审计。
- 业务和管理进程均可运行轻量计划协调器；管理进程不启动生成消费者。业务/worker 持久心跳供后台观察，超过 35 秒未更新显示无有效在线心跳，不以网页仍能打开推断业务在线。

## 上传、任务和付费边界

新的上传会话在排空后拒绝。排空前创建的分片上传可以在既定宽限内续签、传片、确认及完成，截止由数据库判定；修改公告不延长原有宽限。本地预签名 PUT 在接收及落库时都检查维护状态，不能用早先取得的签名绕过截止时间。

TOS 已签发凭证在有效期内仍可能直接写入 staging；服务端的完成/发布接口继续检查维护规则。已发出的素材 GET 能力也不因维护或撤权立即失效，不把维护公告当作已撤销外部签名的证明。

排队但未提交的任务在维护时不领取；刚领取后才开始维护的任务会恢复为 queued 等待。已知上游任务和结果发布可以继续处理，避免已付费结果丢失。

生成适配器的每次付费 POST 经 `submission.paid_post` 复验执行租约、可信发起成员、空间权限、供应商账号绑定和维护状态，并记入 `task_submissions`。**短事务中接受提交是该次调用的准入边界**：之后发生的维护/撤权不会取消这个已准入的在途请求，但会阻止后续批次项、回退或新调用再次准入。网络不明确结果记 uncertain，不据此盲目重发；已有持久任务继续执行原有恢复协议。

批量生图等待所有并发项结束，保留成功部分后独立发布素材、历史和费用，结果标记 partial 及未完成数量。成功图片数与最初请求数分开保存；失败项不会让已成功图片被整批丢弃，也不会将请求的全部数量当作已完成数量计价。

## 画布占用统计与截止时间（第十三批）

管理维护接口的 `activity.canvas_locks` 返回当前范围内的有效占用数：租约未过期、未释放，成员/登录会话有效，空间可用，并且成员仍有画布读取及编辑权限且授权版本匹配。管理进程直接读取共享数据库，不依赖工作台进程内存或在线心跳。查询复用画布协议的持有者鉴权，按成员、会话、空间和授权版本分组检查；读取不续租、不释放或修改租约，也不返回令牌或画布正文。

后台显示有效画布占用和未保存页面；更改维护状态前展示当前占用数量。占用是查询时的快照，不代表浏览器草稿已经保存。未保存页面报告尚未接入，`unsaved_pages` 仍为 null，`pending_checks` 明确包含 `unsaved_page_reporting`；`database_stop_ready` 保持 false。进入只读/暂停/恢复检查后的租约撤销不会清除成员本地草稿。

平台与空间同时排空时，有效状态现在返回两者中更早的收尾截止，与后端逐层检查及续租上限一致；此前同级状态的显示优先级可能让页面提示较晚的平台截止。该修复同时适用于管理维护查询与成员最小状态接口。

新增 10 项实库用例，覆盖双空间与平台统计、读取无副作用、到期/释放、会话退出/过期、成员停用、空间撤销、角色降权、授权版本变动、空间归档、只读撤销，以及两种截止先后顺序和实际续租上限。完整结果：PostgreSQL **132 通过**；Python **120 通过、132 云测试跳过、7 subtest 通过**；CJS **212 通过**。初次全量运行因测试子进程 PATH 缺少本机 FFmpeg 失败；补齐实际安装路径后全量通过。

浏览器使用独立随机 `management_ui_*` schema：另一进程通过成员/画布服务创建 classic、smart 各一份有效租约，管理页面从 0 刷新为 2，全平台和设计空间均显示 2；空间进入排空时仍为 2，改为只读后为 0，其他空间保持正常。未启动工作台/生成消费者，未保存页面始终显示未知。截图 `.local/cloud/acceptance/maintenance-lock-counts.png` 记录初始 0/未知展示；完整回归日志为 `maintenance-locks-final-tests.log`、`maintenance-locks-cjs.log`。预览结束后正常清理本轮 schema。

以下仍是完成门槛：失联/关闭页面报告的人工核对、双画布完整维护和故障联调、任务人工核对/恢复、受控本机维护恢复工具、备份与部署前置检查、旧共享入口最终下线及完整迁移恢复演练。占用统计与租约收尾的交付不代表完整排空、停库或发布流程已经验收。
