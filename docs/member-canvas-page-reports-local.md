# 双画布页面保存报告：本地实现与验收

第十五批为独立管理平台的维护中心接入页面保存报告。追加 migration 010；开发库仍为 001–003，004–010 尚未应用。全部测试使用临时 PostgreSQL schema 和本地对象模拟，未调用真实付费模型。

## 报告与权限边界

经典和智能画布共用成员客户端，上报页面 UUID、递增序号、是否未保存、是否关闭；不上传草稿正文、登录凭证或编辑令牌。成员、登录会话与空间从服务端认证上下文取得，接口要求本空间 canvas.read，不授予编辑权限。报告在排空、只读、暂停访问及恢复检查期间仍可接收，不修改画布版本或租约。

每次页面挂载产生新的报告 UUID；主键同时绑定画布、成员、空间和登录会话。只接受更大序号，重复或乱序报告不刷新时间；关闭后的记录不能被延迟心跳重新打开。报告周期为请求结束后 10 秒，单次超时 5 秒；输入防抖后及保存刷新收尾也会报告。普通自动保存后的状态最迟由下一次成功心跳更新，统计反映最后一次收到的报告。

离开页面尽力发送 keepalive 关闭报告。浏览器缓存往返时暂停编辑与报告定时器，返回后沿用页面报告身份恢复心跳，编辑资格需要重新确认。报告网络失败独立提示，不把失败误当作租约撤销；账号或空间不匹配后停止旧页面报告。

## 维护中心含义

- 在线上报：35 秒内收到报告，且成员、会话、空间和授权版本仍有效的页面。
- 在线页未保存：上述页面中，最后报告仍有未保存内容的数量。
- 失联：已报告但超过时限或授权失效的未关闭页面；另列最后报告未保存的数量。
- 关闭时未保存：明确关闭时仍报告未保存的页面，不因离开就清零。

计数按管理范围过滤，仅覆盖已上报页面，不等同于全部在线成员或全部草稿。失联和关闭时未保存记录不会自动判定为已保存；人工核对、处理留痕与保留策略仍待实现。后台无法代替成员保存浏览器草稿，零计数不证明可以停库；database_stop_ready 继续为 false，未上报页面及备份恢复检查仍是待办。

## 验收

新增 7 项 PostgreSQL 用例覆盖可信身份与空间隔离、严格请求体、只读成员报告不改变画布/租约、乱序及关闭终态、维护中上报、过期与撤权保留未保存信息、多线程最高序号。新增 3 项前端用例覆盖输入/关闭报告、失败与账号切换、浏览器缓存往返。

全量结果：PostgreSQL **139 通过**；Python **120 通过、139 云集成跳过、7 subtest 通过**；CJS **224 通过**。命令分别为 python tools/cloud_test.py --tb=line、python -m pytest -o pythonpath=. tests -q --tb=line、node --test tests/*.cjs；使用项目内 Python 及本机 Node/FFmpeg。日志位于 .local/cloud/acceptance/page-reports-{postgres,python,frontend}.log。

真实浏览器使用 workbench_ui_330a707a480d4972884ea6871be146ae 临时 schema，独立工作台与管理进程联调：

1. 经典画布打开后在线 1、未保存 0；输入后后台未保存变为 1。
2. 同时打开智能画布，在线数为 2；经典画布保存结束并返回后恢复为 1，关闭时未保存为 0。
3. 智能画布编辑后，仅将该测试画布的租约置为过期；保存失败保留内容，后台仍报告在线未保存 1。
4. 确认导出草稿并离开后，后台在线 0、关闭时未保存 1。实库确认经典报告 closed=true/dirty=false，智能报告 closed=true/dirty=true。
5. 切换制作空间，所有页面计数为 0，设计空间记录未混入。失联/撤权和乱序场景由实库测试验证，不将其声称为浏览器断网验收。
