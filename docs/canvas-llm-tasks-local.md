# 画布 LLM 持久任务：本地实现与验收

2026-09-15，第 43 批。使用 PostgreSQL 和 .local 文件对象存储；没有访问真实供应商。

## 已实现

成员画布的经典 LLM 节点、聊天模式及智能提示词 LLM 改为提交持久任务。任务必须带画布 ID、客户端任务 ID、当前编辑凭据和源/目标输入版本；正文相同的同 ID 重试返回原任务，变更正文拒绝。对话历史只允许 user/assistant 文本，图片和视频通过专门字段纳入原素材权限、空间和输入引用校验。

worker 领取 llm 类型，复验成员生成权限、空间分配、供应商原账号和有效执行租约后，使用既有 paid_post 准入记录调用上游一次。回复文本与 raw_usage 先写入确定标识的私有对象检查点，再原子提交成功任务及独立账本。账本事务失败或检查点之后进程中断时，仅恢复保存结果；响应丢失且无检查点的提交转 needs_review，不自动再次付费调用。

费用流水使用 chat 类型保存文本、原用量及提交时价格快照；缺失可计算价格时明确 unknown，不将 token 用量或 0 存储值冒充实际免费。按 token 的供应商专用计价与完整原生协议适配仍需后续验收。

前端通过 MemberCanvasEdit.send 附带编辑凭据，保存输入后提交，按原任务 ID 查询并校验同一回执。输入、连线、成员、空间、节点身份或编辑代次改变后拒绝迟到写回；结果可在生成结果面板独立加入为提示词节点。加入不修改原任务和流水，重复确认不重复追加。

长聊天保留本页完整历史，发送最近 100 条、最多 8 图/3 视频，服务端仍按原历史上下文限制处理。智能提示词的 running 仅为本页瞬时状态，保存和加载均清除，避免结果加入后旧忙碌标记复活。旧同步入口继续只供原非成员模式使用。
