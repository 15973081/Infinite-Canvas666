## 执行顺序

1. 固定本页范围，盘点旧目录及当前 PostgreSQL 的数据来源；先识别会导致丢数据、错误归属或重复付费的迁移问题。
2. 补齐阻碍导入和常规使用的缺口。未知历史身份保留隔离与人工映射，未知上游任务保留记录；不伪造归属、不自动重新生成。
3. 备份并执行迁移，保留新平台已产生的数据；冲突记录到差异清单，不静默覆盖。最终导入采用一致备份，当前在线目录盘点只作为准备材料。
4. 在交付环境集中执行 D1–D4，修复阻断项，交付启动地址、管理员交接方式、配置位置、备份与回退说明。

当前已知环境为本机 PostgreSQL、.local 中的 TOS 文件对象模拟，以及独立画布/管理进程。沿用已确认的本地环境推进，不创建云资源。环境和数据来源须在最终交付记录中明确；本地验证不能记作真实云 Bucket 或远端部署已完成。

## 验收与停止扩张规则

- 日常修改仅运行受影响的专项检查；文档改动检查内容和链接即可，不触发全量测试。
- 第 44 批已有全量数据库及前端基线继续使用。迁移前集中完成上述主流程，不要求再添加一套穷举测试。
- 只有数据丢失/错配、空间越权、恢复自动重复付费、主流程不可用或备份不可恢复阻止交付。
- 普通排版、低频操作体验、极端并发/网络组合进入后续清单，不为这些问题扩展本轮范围。
- 原有测试和保护逻辑不删除、不改为跳过来制造通过结果；发现与本次变更有关的失败仍需修复。
- D1–D4 在明确目标环境通过，迁移差异已说明且有回退步骤后，本轮结束；不会继续把后续优化追加为交付条件。
