## 协议与持久化

图片和视频任务请求新增可选 canvas_target，包含 source_node_id、target_node_id、base_revision。携带该字段的请求必须有成员画布编辑准入，两个节点必须存在于当前已保存画布中，字段版本必须与锁定后的画布 revision 一致。拒绝额外字段、客户端指纹、错误目标和过期版本。

服务器在创建任务的同一事务、现有画布/租约检查之下计算并记录：

- 画布 ID、类型、源节点、目标节点和提交 revision；
- 原始规范化生成请求 SHA-256（含实际提示词、模型、引用和参数）；
- 源/目标及其上游节点、分组成员、连接输入顺序和默认设置的语义图 SHA-256。

绑定存于不可变 tasks.request._canvas_binding，任务读取从该字段返回 canvas_binding，不信任 worker 的 legacy_metadata 副本。重试相同 task ID 时保持最初绑定；即使当前画布已编辑，也不以重试重新拍摄输入。更换目标或请求内容会冲突。

服务器附加的绑定不参与客户端请求幂等指纹；可选空字段不改变旧请求指纹。非对象历史请求的指纹行为也保留。没有新增 migration，没有凭证或完整图快照写入绑定；任务原 request 继续按既有规范保存。

## 输入判断与结果界面

图指纹忽略节点坐标、显示尺寸、缩放、运行状态、pending 和派生预览尺寸。无关节点和节点数组重排不影响绑定。提示词、模型、未知新参数、原媒体、上游生成输出、分组内容、同一目标的引用顺序和默认设置变化都会被保守地识别为变化。

已有生成结果列表附带 binding.state：unbound、unchanged、changed、missing 或 unsupported。该状态只观察已保存文档，不授予写入/提交许可。任务结果、费用及付费提交记录不会因输入变化被取消或重写。

对尚可加入的结果，界面分别说明“原输入已修改”或“原节点已删除或不可用”。加入仍走已有当前编辑租约和画布 revision 保护，新增独立结果节点，保留现在的图和输入。

## 下一步与边界

目前两个画布生成按钮仍沿用原提交格式，不会自动发送 canvas_target。浏览器验收验证的是新协议任务的结果查看/独立加入，不是生成按钮端到端绑定。下一步必须接入：

1. 提交前确认源/目标及输入已保存，再带目标和正确 revision 创建任务；不得把未保存的前端快照冒充数据库基线。
2. 用相同语义规范核对浏览器当前未保存输入，以及服务器返回的持久绑定，再允许自动回填。
3. 区分正常自身回填/批量结果与用户改动，避免第一张结果或正常保存使剩余任务失效。
4. 对旧任务、旧客户端和跨刷新恢复保持明确的未绑定/待加入边界，并补齐 LLM 及完整双成员、断网、休眠和维护矩阵。
