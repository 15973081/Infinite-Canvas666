# 附件引用查询与历史数据兼容

成员附件列表需要判断素材原件及其派生文件是否被引用。历史空间包含大量画布备份时，每次读取全部 JSON 正文会长时间持有成员权限事务，并阻塞登录、维护检查和其他请求。

迁移 033 为画布、空间文档（含历史备份）、生成任务和未彻底清理的在线作品建立候选素材 ID 索引。PostgreSQL 在源记录插入、更新和删除时同步维护索引，不依赖后台补写，也不改变素材归属。

候选索引只缩小读取范围。列表和无旧路径别名的删除检查仍使用原有 `media.id_from_ref` / `contains_ref` 规则逐项确认真实引用。正文中的 ID 子串、JSON 键和外部链接不能单独证明引用。旧路径别名的删除检查保留原有完整校验。空附件列表不再扫描历史正文。

这次迁移只新增函数与索引，不删除素材、提示词、费用或历史记录。大空间首次构建索引需安排维护窗口；构建完成后再启动包含新查询的应用。回滚应用时必须使用包含相同迁移及私有附件权限规则的兼容版本，保留独立删除账本，不要直接恢复旧数据库覆盖新增数据。

验证包括：索引候选不遗漏合法引用、普通文本子串不产生假引用、跨空间隔离、记录更新后结果同步变化、删除保护、私有附件上传/分享/范围预览及查询使用 GIN 索引。
