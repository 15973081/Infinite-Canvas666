# 对话与画布 LLM 计费

## 管理配置

进入管理平台 → 模型与计费 → 选择供应商、类型「对话」和模型。

- **Token 计费**：分别填写输入、输出价格，单位为人民币 / 百万 Token。缓存输入可设置单独价格；留空按普通输入价计算。
- **按次计费**：填写人民币 / 次，一次成功且有非空回复的模型调用计一次。多轮对话的每轮分别计数；生成图片、视频仍沿用原计费规则。
- 两个开关互斥，全部关闭并保存表示明确不计费。单价 0 也可明确配置免费。尚未配置价格的调用显示待核算，不等同于免费。

每个供应商、模型独立配置。输入修改原因后保存，权限、版本冲突和审计沿用原管理平台。**升级不会替任何真实供应商填写单价或自动开启收费。**

## 核算与账单

GPT 对话（流式和非流式）、经典画布和智能画布的 LLM 调用复用同一价格规则。
调用提交时冻结价格，后续修改不会重算已提交调用或历史金额。

Token 金额 =（总输入 − 缓存输入）× 输入价 + 缓存输入 × 缓存价 + 输出 × 输出价，再除以一百万。
缓存输入包含在总输入内，推理 Token 包含在供应商输出内，不重复相加。
金额使用 Decimal 计算，最后一次四舍五入到百万分之一元；前端只展示服务端结果。

只采信供应商的实际输入/输出用量。缺失或格式异常时标记待核算，不估算，不自动切换按次计费。
请求被上游明确拒绝且没有有效用量时不计费。网络中断等结果不明的按次调用待核对，不自动重发。
Token 模式收到有效用量时仍按实际用量核算，即使随后连接异常。

对兼容 OpenAI 的流式接口，Token 模式默认请求 `stream_options.include_usage`。
代理不支持此参数时可关闭「请求流式用量」，系统不会为补用量再发一次调用。
参考：[官方流式响应与 usage 说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。

GPT 回复下方展示模式、用量和金额；个人费用与管理平台账号费用可查看调用归属、模式、价格、Token 与待核算原因。
账单归属于服务端认证的发起人，删除对话不删除账单。团队共享数据导出排除个人对话费用明细；完整数据库备份保留它们。

## 数据库与部署

新增迁移 `026_chat_billing.sql`：

- 新增 `ai_chat_calls` 保存调用状态、发起人、对话 ID、价格快照、用量与费用条目关联，不保存完整提示词或回复。
- `ledger_owners` 新增 `chat_call_id`，每条归属必须且只能关联一个任务或对话调用。
- 继续复用费用账本与权限，不修改旧任务金额。

PostgreSQL 模式在请求上游前事务性建立待核算条目，结束时锁定调用并一次性结算。重复结算不会新增费用。
进程异常退出留下的 pending 调用仍可在账单中看到待核算，当前阶段没有自动对账/补用量功能。
旧 SQLite 模式兼容返回费用，但不具备此 PostgreSQL 持久化调用审计能力。

部署前备份数据库，在正确数据库/Schema 上运行现有 `database.migrate()` 流程，重建管理静态资源并重启工作台、管理平台与 worker。
当前功能是费用核算与流水，不包含充值、余额扣款、支付、欠费拦截或供应商账单自动对账。
