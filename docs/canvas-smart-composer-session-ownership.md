# Smart composer 输入目标会话所有权（第一轮）

日期：2026-10-04。Smart 全景已提交 `d3c5576`；选择/composer 划界方案已独立提交 `ebeeb7f`。本轮只实施划界方案第一轮，不宣称选择和整个 composer 整理已经完成。

## 范围与协作收益

workspace 的 `createSmartComposer()` 私有持有 `lastComposerNodeId`、`activeComposerSubject` 和 `smartComposerBaseline`，并记录目标画布与自身暂停/销毁状态。入口只初始化和绑定功能对象。冻结 UI 快照仅包含打开、节点 ID、目标有效、画布 ID、暂停和销毁标量，不暴露 DOM、节点或 baseline。

输入 DOM、节点草稿、当前 settings 仍是既有数据，不建立第二份存储。显示基线是判断真实用户编辑的派生快照，不能用 UI 默认值替换已提交任务输入。节点/多选/图片选择在本轮保留，后续按划界方案单独收拢。

| 责任 | 操作边界 |
| --- | --- |
| 当前 composer 目标、切换标记、显示基线 | smartComposer 唯一所有者 |
| 选择目标后的完整输入切换 | refresh 完成旧草稿同步、新目标绑定、草稿与设置加载、控件和布局更新、基线记录 |
| 草稿修改、保存投影及设置持久化 | saveDraft、changes、setDraftForNode、persistSettings；实际内容仍归原节点 |
| 文档恢复/替换 | documentReplaced 使旧绑定失效；现有 render 再按当前选择建立新会话 |
| 工作流导入 | documentImported 保留原“清设置对象、保留旧草稿切换标记”的差异，原 render 完成切换 |
| 生成输出/级联收尾 | outputSelected、finishCascade 保留原 UI 效果；执行模块不用改会话字段或关闭 DOM |

原有 `activeSettingsSubject()`、`activeComposerNode()`、`smartComposerChanges()`、`savePromptDraftForCurrent()`、`persistActiveSmartSettings()`、`clearPromptInput()`、`setPromptDraftForNode()`、`updateComposer()` 保留薄委托。其他模块不再读取或修改三个会话字段。

## 保持的差异与生命周期

A→B 先把实际编辑写回 A，再载入 B 的草稿及节点设置；相同目标刷新保留未保存差异，不把渲染产生的默认模型/尺寸当作用户编辑。富文本及媒体 token 的存取算法保持原样，`preserveDraftOnce` 与 `promptLocked` 继续使用原输入 DOM 标记，本轮未另加一份状态。

普通关闭可同步草稿、清理绑定/基线和输入锁；清选择会清空输入，选择非图片节点保留原关闭规则。静默级联和任务收尾保持既有差异，不额外调度保存、创建撤销记录或改任务设置。

目标绑定核对画布 ID 和节点身份；同 ID 对象替换或换画布后，旧草稿不能投影到新节点。节点保存产生的图片元数据复制不会改变节点身份，也不会使 composer 失效。

重复绑定只清除自身两个 pagehide/pageshow 监听；不移除工作区、提及输入、素材库、编辑器及媒体预览监听。缓存暂停停止 UI 切换/修改，保留输入和绑定；任务输入查询及原有后台保存仍能读取/同步有效草稿。返回时刷新当前选择并保留真实未保存编辑。永久销毁清理自身监听与会话，迟到 UI 调用无效，不删除节点或任务数据。

文档与 execution 每个文件仅替换两处原有 UI 字段操作，逐文件与基线比较确认其余代码相同。保存、撤销、任务输入绑定、请求、恢复和写回算法未改变。设置的共享读取与运行快照不移入 composer。

## 验证

第一轮实施前运行 139 项 composer、任务输入绑定、任务写回和局部性能相关基线，全部通过。适配隔离 VM 测试时使用实际 composer 功能对象建立输入基线，不向私有字段注入测试值；纯任务清理测试通过 UI 通知接口替身隔离视图。

新增 2 项所有权测试与 9 项真实生产页面浏览器测试，覆盖冻结状态、构造、无外部字段读写；默认值不回写；富文本 A→B→A 与设置切换；保留草稿一次的生成语义；非图片和空选择；同 ID 节点/画布替换；真实撤销后的输入恢复；重复绑定、缓存返回、销毁后调用；只读切换和保存次数；缓存暂停期间后台保存。

现有 142 项任务输入/写回、删除与局部刷新相关测试通过。浏览器同时验证已有“查看待处理结果不改输入指纹”“真实输入编辑仍使绑定失效”等路径。

最终全量结果：**1113 项 JavaScript 全部通过**（含新增 2 项所有权与 9 项真实页面测试），相关 **51 项 Python 通过**；48 个 JavaScript 文件语法检查与差异检查通过。原始盘点与两份复盘文件未修改。

另尝试云端结果/任务绑定专项：普通 pytest 按项目要求跳过 24 项，改用 `tools/cloud_test.py` 后本地 PostgreSQL 连接超时，专项未执行，不计入通过数。执行模块核心逻辑未变；本轮任务语义由真实前端输入绑定/写回回归验证，不能据此宣称云端专项已经通过。

## 剩余范围

Smart 主选择、多选和图片子项选择仍有跨模块写入，留待第二轮分类收拢；不是本阶段已解决的问题。输入 DOM 标记、提及与尺寸拖动等共享交互未移动，节点草稿及 settings 的存储结构未改变。真实生成服务和大画布耗时基准未运行。

全局总计划仍包含后续选择命令、输入应用协作核对、渲染/几何缓存、管理 UI 和总体验收。保存、撤销历史、锁、同步、任务协调和服务端版本一致性继续留在独立专项。
