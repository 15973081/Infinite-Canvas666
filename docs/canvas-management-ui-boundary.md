# 剩余管理 UI 的收益核对

日期：2026-10-05。此文件限定总计划第五阶段；第四阶段工作区缓存正在完成最终回归，不在此扩展生产逻辑。

## 保留的单模块管理状态

Classic 管理页的画布搜索、排序、文件夹视图、移动目标、删除/清空回收站确认及图标选择，读写集中在 `canvas.js` 的管理视图逻辑。现有搜索/排序入口已统一刷新列表，重绘卡片通过 onclick 等替换处理器；本轮没有需要外部调用方协调多个 UI 字段的证据。保留其单模块所有权，不为缩短文件或减少变量再建立通用管理控制器。

Smart library 的模板、预设及素材会话已有各自所有者；词库缓存、本地预设、分组和覆盖数据属于原内容存储流程。保留共享内容数据，不复制管理侧的一套库/分类选择。

## 有实际清理收益的下一块

Classic library 的管理弹窗仍有四个入口声明的 UI 绑定：当前 tab 和资产/工作流/提示词多选集合；两个 DOM 引用同样在入口声明。业务使用集中于 `canvas-library.js`，所以不能宣称消除跨文件的大量直接写入。但 `bindClassicAssetManagerEvents()` 每次通过 addEventListener 添加打开按钮、tab 和模态窗口处理器，缺少本弹窗的解绑/销毁记录，反复绑定会累积；弹窗加载回执、内容重绘及其上传控件也没有统一 UI 生命周期。

建议仅由 library 的管理弹窗功能持有这四个状态、两个 DOM 及自身监听，冻结查询，保留原打开/关闭/刷新函数薄委托。素材/词库所有者通过“共享选择已变化”“项目已删除”等通知清理相应多选，不直接取得 Set；库与分类继续使用现有 `classicAssetPanel` / `classicPromptPanel` 的完整命令，不复制选择。

保留差异：打开清资产与提示词多选，但保留工作流多选；tab 切换、切库和切分类保持目前各自清理规则。已提交上传/管理写入继续完成原内容更新；关闭或销毁只使旧 UI 刷新、控件回绑失效，不能取消已提交任务或更改服务端写语义。不扩展词库响应竞争或服务端版本一致性。

针对性验收包括：重复绑定后一次点击只有一次打开/写入；共享库/分类命令清理正确集合；资产/工作流/提示词入口与原权限一致；关闭/重开期间迟到加载不能恢复旧 tab/选择；已提交写操作关闭后仍完成但不重新打开；缓存离开/返回与永久销毁只清自身监听。Classic 管理视图和 Smart 其余内容状态保留的理由应在最终逐项复盘中记录。

此记录为第五阶段的核对与实施边界，不宣称管理弹窗整理已经完成。
