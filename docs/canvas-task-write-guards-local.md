# 异步任务回填与外层收尾保护

本批对应协作升级计划 C3 / TK-1，补齐图片、视频任务的外层回调和收尾。2026-09-14。

## 已修复

原来轮询拒绝交接后的响应时，调用方仍可能继续执行“没有输出”的失败处理，删除智能画布等待分支、移除 pending 或改写运行状态。网络报错及延迟定时器也可能绕过成功响应处已有的保护。

两种画布现在用共用守卫绑定启动时的成员、空间、编辑会话、epoch、generation、画布 ID 与原节点对象。源节点或目标被删除/同 ID 替换、切换画布、暂停或交接后，迟到回调停止回填。暂停错误向生成和串联调用方传播；不再按普通生成失败清理等待节点或追加失败日志。

- 经典图片/视频：提交返回、保存之后、轮询成功及失败、串并行流程和重试收尾都复验。轮询绑定原 pending 记录，视频重试在失效后退出。
- 智能画布：提交、等待恢复、串联输出、循环输出均有复验；旧 generation 的结果保持待处理，外层不会删除分支。视频提交拒绝不能删除被替换的 pending 记录。
- 手动查询：同时检查源节点、目标节点和具体 pending 记录；迟到的成功、失败及 finally 不再修改新状态。智能查询成功移除 pending 后仍明确刷新和安排保存。
- 定时清理：经典一键运行上下文和智能运行 token 只清理自己持有的运行记录，不动同 ID 的新运行。旧回调不重置新节点运行状态。

正常经典保存会更新外层 canvas 对象，因此回填身份使用稳定画布 ID，并继续检查原编辑会话和节点对象；不会把正常保存误判为画布切换。新增用例实际调用 saveCanvas、runGenerator/runVideoNode 和轮询函数，验证提交后保存及轮询中再次保存均可完成。

## 继续保留的范围

本批是运行会话和节点对象层面的保护，不是持久输入版本绑定。相同节点对象上的提示词、模型、引用及连接变更仍需建立提交快照/指纹，并与后台任务和当前目标版本核对。跨刷新后的目标关联也仍需持久校验。
