# 工作台保存刷新与画布收尾

本批修复工作台嵌入画布在前端更新时的收尾流程，范围包括经典和智能画布、成员退出及切换空间所调用的刷新前检查。开发库未迁移；全部浏览器操作使用一次性的本地 PostgreSQL schema 和对象模拟。

## 实现

- 前端版本控制器递归收集当前页面及同源 iframe 的保存检查，等待所有结果；原实现只派发父窗口事件，无法确认嵌入画布保存完成。嵌套页面按窗口去重，不重复派发。
- 检查最多等待 45 秒。失败、拒绝或不可读取的子页面阻止刷新；界面提示保留草稿并允许重试。迟到的成功结果不再触发导航；重复点击共享当前刷新请求。
- 成员画布先暂存当前草稿，再冻结编辑并提交最终保存，确认对应 revision 的租约释放后才允许刷新。失去编辑资格且仍有未保存内容的页面拒绝刷新。原草稿保留，保存失败不释放租约；释放结果不确定同样阻止刷新。
- 经典画布等待已有保存请求结束，而不是把等待本身记成新的保存需求；保存中产生的新内容立即接着保存，避免依赖会被收尾状态取消的延迟计时器。冲突保留内容，收尾不自动重发失败请求。
- 成员退出和空间切换在版本控制器可用时复用相同的子页面检查。画布 URL 已有的空间和画布参数在版本刷新时保留；工作台根页面刷新后仍按既有行为回到画布列表。
- 更新提示条上移，避开桌面布局底部的编辑、草稿和成员操作。它不提供忽略失败强制刷新的按钮。

## 验证与边界

新增 9 项前端用例覆盖：嵌套 iframe、重复点击、失败后的明确重试、超时及迟到结果、拒绝和不可访问的子页、草稿暂存/释放顺序、无资格页面、经典在途保存与新输入竞态、冲突不重试。完整 CJS **221 通过**；Python **120 通过、132 云测试跳过、7 subtest 通过**；PostgreSQL **132 通过**。

实际浏览器在工作台 iframe 中打开两种画布，创建提示词节点，改变临时静态构建标记触发更新公告，然后输入文本并立即点击“保存并刷新”。两次均完成整页刷新，重新打开画布后文本完整且处于查看模式。实库复核经典 revision 3、智能 revision 4，各有一条正常释放事件。截图为 `.local/cloud/acceptance/frontend-refresh-classic.png` 和 `frontend-refresh-smart.png`。

失败场景使用同一隔离 schema：智能画布输入新文本后令测试租约过期，再点击刷新。实际保存被拒绝，页面未跳转，更新提示恢复可操作并说明保存未完成；新文本仍在画布上，本地草稿列表显示本页基于 revision 4 的记录。数据库复核智能画布仍为 revision 4、此前文本和一条释放事件，不把失败内容当作已提交。截图为 `frontend-refresh-failure.png`，脱敏合成数据复核文件为 `frontend-refresh-db.json`。临时构建标记已移除，两个预览进程正常退出并清理本轮 schema。

上述用例不等于所有断网、后台任务回填、维护排空和恢复演练已经完成；45 秒超时并不代表可以取消服务器已经接收的保存，也不代表浏览器外的未上报草稿已经保存。整体 C3/M3/M4 仍在实施。
