# 图片逐图回执与原任务恢复验收

## 本批行为

第 44 批在每次异步图片响应取得上游任务编号后、首次查询之前保存私有回执；每张图片返回的来源和用量也独立保存，不再等同批全部完成才保留。一次请求的 1–8 张图片使用独立序号，回执和结果分开使用确定的素材 ID，内容不可覆盖，发布受工作区和当前执行租约约束。

检查点沿用 task-result-source 私有角色，普通素材读取、签名分享与输入资产引用均不可使用；不会把内联图片或供应商原始响应塞进任务列表。无需数据库 migration。

- 中断任务的全部位置都有结果或原提交编号时，worker 恢复查询；已有结果直接复用。缺失任何位置的回执，保留待核对状态，不自动补发。
- 管理平台的任务处置显示请求张数、已保存结果、可查询数及缺失数。恢复使用原供应商账号，并复验权限、版本和执行占用；处置幂等且留审计。管理接口本身不请求上游生成。
- 维护排空和取消供应商新任务分配后，仍可查询已提交任务；凭据或接口绑定变化时拒绝使用新账号恢复。
- 历史单图任务可复用原任务行中的单个编号；该编号不得扩展为多图回执。查询断网后保留原编号，查询地址将编号编码成单个路径段。
- 总结果检查点和费用账本保持既有原子提交、固定输出槽位和重试规则。
