# 对话上下文预算

字符引用上限仅决定能否导入或选取 Skill，不能证明所选模型能接收全部内容。现在普通和流式聊天都在保存消息、创建计费记录和请求模型前，校验最终发出的上下文。预检覆盖系统提示词、最近的历史消息、历史 Skill 快照、当前 Skill、附件解析正文和图片。

管理端供应商配置增加 `chat_context_limits`，键为准确的聊天模型名，值为 1,024 到 50,000,000 的整数 token 上限。例如：

```json
{"chat_context_limits":{"your-chat-model":131072}}
```

容量应按实际供应商文档设置，平台没有硬编码模型规格。修改其他配置而省略此字段时，原有容量配置保留。未配置的模型采用 `CHAT_DEFAULT_CONTEXT_TOKENS`，默认 131,072；界面明确称为平台默认上限，不能将其理解为模型真实规格。默认回复预留由 `CHAT_OUTPUT_RESERVE_TOKENS` 控制，为 4,096，且不超过总容量的四分之一。

`POST /api/chat/budget` 使用与发送相同的权限、成员身份、模型配置和文档解析，只返回预算，不保存对话、不计费、不调用上游。前端发送前调用它；后端发送接口再次校验，客户端无法通过改写预检结果绕过限制。超限返回 413 和 `chat_context_over_limit`，输入、附件引用和 Skill 选择保留，方便拆分或切换模型。

当前估算取正文 UTF-8 字节数作为保守文本 token 上界，并加上消息协议开销和每张图片的预算（`CHAT_IMAGE_ESTIMATE_TOKENS`，默认 16,384）。不是模型专用 tokenizer 的精准计数，尤其图片、不同模型协议和回复长度仍有误差。保守估算可能比实际用量高；实际计费仍使用供应商返回的 usage。回复预留是预算，不会强行改写各供应商的生成参数；供应商仍可能拒绝其实际容量超限请求。

验证包括边界值、中文 UTF-8、图片、历史、模型配置校验、普通及流式接口在保存历史及计费前拒绝超额，以及浏览器超限时保留输入。大 Skill 测试使用明确配置了足够容量的模拟供应商，不宣称任意真实模型均支持 600 万字符。
