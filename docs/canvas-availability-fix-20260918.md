# 画布打开及空间切换卡顿修复

2026-09-18 正常开放历史空间后，画布的素材存在性检查沿用了本地文件检查逻辑。云端该逻辑会从 TOS 下载完整原文件；异步接口直接执行同步下载，阻塞工作台事件循环，连空间列表、登录状态请求也会超时。

修复将云端检查改为 PostgreSQL 批量元数据查询，并使用同步路由的线程池执行。查询限定当前空间及素材来源命名空间，排除未就绪、已删除和内部任务素材；缺失引用返回 false。本地部署维持原文件检查行为。检查接口不再下载 TOS 文件，正式素材仍在 TOS。

工作台已部署 `76fdee4-presence-fix-20260918`，其他服务未改变。变更为 `app/routers/canvas.py` 和新增 `app/storage/media_presence.py`；后续部署须同时携带这两处变更。此次未部署此前独立迁移工具的修改。

验证：

- 3 项回归测试通过，覆盖批量查询、空间条件、慢查询期间其他请求响应、本地兼容。
- 实际管理员接口：最大的三个迁移画布（554、421、411 个节点）均返回 200，耗时 556～834 ms。
- 3,000 条素材引用检查返回 200，耗时 216 ms；同时发出的四次空间列表请求耗时 45～115 ms。
- 跨空间引用及缺失素材返回 false；匿名请求返回 401。
- 四个生产服务均正常。未修改历史记录、素材对象或权限，未触发付费生成。
