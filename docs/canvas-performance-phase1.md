# 画布首屏优化：第一阶段

## 改动范围

- 在现有 `VersionedStaticFiles` 内对不小于 1 KiB 的 JS/CSS 协商 Gzip；使用 Python 标准库，不增加运行时依赖。压缩结果按文件内容版本缓存，最多保留 128 项。
- 保留静态资源鉴权、版本重定向和长期缓存；压缩与原文使用不同 ETag，并返回 `Vary: Accept-Encoding`。Range 请求继续使用原文，HEAD 与对应 GET 的响应长度一致。API、HTML 和媒体响应不进入本次压缩逻辑。
- 两份品牌字体转换为 WOFF2，保留原 TTF 和许可证。未裁剪字形，已比较字形顺序、轮廓、字符映射、排版数据、可变字体数据和名称元数据。转换工具仅在开发时使用，部署直接使用已生成文件。
- 普通/智能画布共用的 `CanvasApi.getLocalAssets()` 在成员模式下跳过旧本地目录请求；空间素材仍通过原有 `/api/asset-library` 和权限传输层读取。后端对旧接口的 503 限制保持有效。

脚本执行顺序、8 模块边界及生成任务逻辑未调整。

## 本地 Lighthouse 结果

登录后运行 Lighthouse 13.5.0 桌面配置，每个页面测试前清除浏览器资源缓存，保留登录状态。
优化前为此前单次基线，优化后连续三次，以下采用中位数。首次运行也包含服务重启后的压缩缓存构建。

| 页面 | 原性能分 | 优化后三次性能分 | 中位数 | LCP 原值 → 新中位数 |
| --- | ---: | --- | ---: | --- |
| 工作台 | 98 | 100 / 100 / 100 | 100 | 1.04 s → 0.60 s |
| 普通画布列表 | 64 | 92 / 93 / 95 | 93 | 3.40 s → 1.34 s |
| 智能画布空白页 | 74 | 96 / 96 / 96 | 96 | 2.46 s → 1.12 s |
| 管理后台 | 100 | 100 / 100 / 100 | 100 | 0.45 s → 0.45 s |

第一轮总传输量：普通画布 3,048,339 → 768,658 字节，智能画布 2,047,126 → 640,131 字节。
智能画布三轮控制台均未再出现旧素材接口 503，最佳实践从 96 提升至 100。
报告保存在本地忽略目录 `.local/lighthouse/phase1/run-{1,2,3}/`，基线保留在 `.local/lighthouse/reports/`。

这些结果衡量列表和空白页首屏，不代表数百节点画布的拖动、缩放或生成耗时。
当前收益足够，后续 Tailwind 预编译和模块延迟加载另行评估。
