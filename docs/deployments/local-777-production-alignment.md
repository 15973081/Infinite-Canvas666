# 777 本地环境与 2026-10-27 生产快照对齐

代码以 `codex/production-2026-10-27`（`0f590e8d`）为兼容基线，合入 `codex/seedance-draft-upgrade`，保留普通画布逐视频升级和智能画布样片流程。

本次生产差异包括工作台和管理端的显式来源白名单，以及画布首页文件夹下拉菜单的滚动修复。头像、成员资料、费用、个人数据和空间权限的代码原本已存在；缺失原因是旧的本地启动脚本强制设置了 `AUTH_MODE=shared`。

## 本机启动

在 777 项目根目录执行 `powershell -ExecutionPolicy Bypass -File .local/start-local.ps1`，启动工作台、管理端和独立任务 worker。入口为：

- 工作台：`http://127.0.0.1:18777/`
- 管理端：`http://127.0.0.1:18779/`

启动器复用已保存的成员环境，不重建数据库。登录信息保存在本机忽略目录 `.local/member-cloud/runtime/access.txt` 和 `credentials.json`，不会随 Git 发布。关闭服务可用同一 Python 环境执行 `.local/member-services.py stop`。

## 数据边界

777 使用独立数据库 `canvas_777_production_20261027`、schema `production_20261027` 和独立对象目录 `.local/member-cloud/objects`。原有 666 本地服务及其数据保持不变；没有连接或变更线上生产数据。

原本地成员库的迁移版本高于生产快照，因此保留完整数据库快照和原 schema，并向符合生产版本迁移校验的新 schema 导入兼容表，而非修改迁移版本号绕过校验。启动时继续执行正常数据库版本检查。

导入时保留了 5 个成员、4 个空间、8 张成员画布和 186 个素材记录，并追加保留 777 共享模式下的 2 张空画布，共 10 张。原共享模式文件仍保留在 `data/canvases`。此副本用于本地开发，后续不会自动与原服务或线上数据同步。

## 验证

已在真实本地成员服务上通过登录页面验证头像、账号菜单和成员资料弹窗。样片测试使用模拟供应商响应，覆盖普通画布多视频独立升级、失败重试、刷新恢复和重复提交防护，不产生付费视频任务。
