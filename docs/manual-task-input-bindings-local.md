# 双画布手动任务恢复与输入绑定验收

2026-09-15，第 42 批，C3 / TK-1。目标是恢复成员模式中的图片任务手动查询，并防止旧结果覆盖后来修改的输入。

## 发现与实现

旧按钮调用 /api/image-task-query，直接携带上游任务 ID 和当前供应商。成员网关尚未开放该旧路由，实际会拒绝请求；旧前端回调本身也没有语义输入校验。两种画布现在使用 pending 中保存的原本地任务 ID，通过已授权的 /api/canvas-image-tasks/{id} 读取持久任务状态，不改变供应商账号，不发起新的生成提交。

同一页面的原输入绑定仍有效时，复验成员、空间、画布、编辑代次、源/目标节点对象、当前 pending、任务 ID、不可变任务回执及输入指纹，然后同步回填一次。轮询显示失败或待核对状态时保留已经验证的回执，使后续成功结果仍可受控加入；成功回填才消费回执，禁止重复写入。

刷新后的 pending 不恢复原内存回填权，旧编辑代次或输入变化也不自动覆盖原节点。结果成功时直接打开现有“生成结果”面板，用户可确认加入为新节点，沿用服务端当前版本、租约和幂等检查。浏览器复验发现经典状态栏提示不明显，因此改用此可见面板。缺少本地 ID 的历史记录提示管理核对，不猜测映射或退回旧上游查询。智能画布收到已删除任务按钮的 ID 时不再退选另一条待恢复任务。

仍在执行的任务只显示当前状态；needs_review 引导到管理平台核对，不自动重提。此批没有实现成员按钮直接向上游发起重新查询；已提交任务的后台查询/管理核对仍由现有持久任务服务承担。非成员旧模式保留原有查询行为。
