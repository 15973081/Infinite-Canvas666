# 火山云上线计划（精简版）

更新：2026-09-14
状态：PostgreSQL + 本地 TOS 对象模拟已完成存储验收，真实云资源上线仍待实施。新增线上成员协作计划，本次只更新文档，成员账号与数据库画布锁尚未实施或部署。

## 目标

先把现有项目搬到火山云，迁移画布数据和素材，跑通上传、生成、保存、裁剪、导出。

第一版按一个共享工作区使用，供自己和少量可信使用者访问；共享画布和素材不按创建人拆成私有空间。线上协作升级采用个人成员身份及查看者/编辑者/管理员基础角色，成员由管理员开通；不开放匿名调用生成接口。此约定替代之前“暂缓独立用户身份”的计划。

沿用 ECS + PostgreSQL + TOS：ECS 运行应用和媒体处理，PostgreSQL 保存画布、素材索引及必要的任务记录，TOS 保存图片和视频。先用单机部署，不引入 Redis、独立任务集群或复杂后台。

## 工作计划表

| 步骤 | 工作内容 | 依赖 | 上线标准 |
|---|---|---|---|
| 1. 部署准备 | 盘点现有数据和路径；准备 ECS、PostgreSQL、私有 TOS；整理启动命令、配置和密钥；确认地域、域名及公网访问条件 | 云账号与资源配置 | 应用可在云服务器启动；数据库、TOS 连接成功；密钥仅在服务端；原始数据已有备份 |
| 2. 画布数据上云 | 将画布和必要业务记录迁到 PostgreSQL；保留原 ID 和引用关系；使用一个默认共享工作区 | 1 | 旧画布可打开、编辑、保存；刷新、重新部署和重启后数据仍在；同一画布冲突保存不会静默覆盖 |
| 3. 素材上 TOS | 统一上传、读取和对象标识；把原素材搬到私有 TOS；建立旧路径到新对象的映射 | 1；与 2 联调 | 新旧图片和视频均能预览；过期链接能刷新；画布保存稳定对象标识，不永久保存签名链接；迁移文件数量、大小和校验结果可核对 |
| 4. 跑通媒体流程 | 改造参考图、裁剪、导出等本地路径依赖；所需素材临时下载，处理后回传 TOS；设置临时目录清理及全局并发上限 | 2、3 | 上传→生成→保存→重开画布→裁剪→导出均通过；处理完成后临时文件可回收；磁盘不足时停止接收新处理任务 |
| 5. 上线基本保障 | 入口认证、HTTPS、服务自动启动、日志轮转、定时备份；保存必要任务状态和供应商任务 ID | 1–4 | 页面、API、实时连接和素材入口均受保护；服务器重启可恢复服务；中断任务可查询或明确标记待处理，不永久转圈，也不盲目重提付费任务；完成一次备份恢复验证 |
| 5a. 线上成员协作 | 按 C1→C2→C3 实现个人身份、PostgreSQL 编辑租约、服务端写入校验、交接及断线恢复；两种画布统一，不显示 IP 作为成员名称 | 已完成的本地存储基线；云端联调接续 1–5 | 多成员与同账号多窗口可区分；旧锁/伪造身份不能写入；查看、接手、草稿恢复及角色限制通过；旧共享认证不能绕过新权限 |
| 6. 迁移与试用 | 先演练再停写旧系统，完成最终迁移和身份映射；切换到云端；自己或 1–2 名可信使用者用各自账号试用 | 1–5a | 核心流程可连续使用；画布和素材无未解释的缺失；协作验收矩阵通过；备份和旧环境保留；需要回退时先保全云端新增数据 |

云端执行顺序：1 → 2/3 → 4 → 5 → 5a 联调 → 6。5a 的 C1–C3 开发和本地验收可以先在现有 `.local/cloud` 完成，不依赖创建云资源；详见[线上协作升级计划](online-collaboration-upgrade-plan.md)。具体工期在身份与写入路径盘点后估算，不沿用此前完整账号体系的 6–9 周排期。

## 这次暂缓

- 公开注册、邮箱验证、邮件找回密码及完整邀请运营体系；本轮仅提供管理员开通、一次性激活及重置入口。
- 多工作区、逐画布自定义权限及大型管理后台；基础角色与必要成员管理纳入 5a。
- 逐用户额度、余额、扣费与费用分摊；保留已有费用记录和云平台分账配置。
- 分布式队列、复杂任务自动恢复、Redis、CDN 和多机扩容。

## 必须保留的三点

1. **访问保护**：共享工作区意味着进入的人共用数据，不能把它当作个人私有空间；云密钥不放到浏览器。
2. **素材完整性**：不能只替换预览 URL；参考图、裁剪和导出都必须通过统一素材访问层。旧文件核验前不删除。
3. **持久化与恢复**：数据不放临时容器目录；定时备份并验证可还原。切换时只保留一个写入入口；云端已有新数据后，不能直接切回陈旧本地备份。

上线验收以表中标准为准，重点检查“能用、数据不丢、文件不堆满服务器”。
