基线：`2ca5dc9`。本轮仅新增诊断工具和记录，未修改生产 JavaScript、CSS 或 Smart 刷新范围；原盘点、框选性能快照均保留。工作区中两个既有 Classic 文件仍仅有换行差异。

## 收尾决定

原定状态整理和六轮模块边界计划正式收尾，已提交的框选优化 `2ca5dc9` 保留。用户先将本诊断降为参考并撤回继续实施建议，随后明确授权仅完成已经划定的 Classic 端口集中读取这一轮，再正式收尾。

最后一轮授权范围：只调整 Classic 选择呈现时的读写顺序，每次读取实时端口，复用单次 points 和连线 DOM 缓存；不增加跨事件坐标缓存，保留几何、拓扑、临时线、刀切、保存及撤销。先单独提交本诊断，再以独立实现和验收提交完成回归、两批反转顺序采样及小图 p95 确认。

继续保留原生 JavaScript，暂不迁移 React；本轮不修改 Smart 或 canvas-selecting CSS，剩余成本只记录。最后一轮完成后停止自动扩展性能优化和架构工作；后续仅由明确的功能需求、维护障碍或已确认缺陷驱动，另行立项。

完成标准为：功能有明确所有者、调用入口完整、生命周期清楚、修改时需要理解的模块更少。全局变量数量和单项性能数字不作为持续扩展本轮工作的理由。本次修正只更新文档，未修改生产代码或重新执行测试、性能采样；原始测量数据保留。

## 诊断结论（参考）

曾评估在 **Classic 选择呈现入口**集中读取当前端口后再更新路径和按钮。两批诊断中，1000 节点同步 p50 下降 **35.9%／39.7%**，第二帧 p50 下降 **28.1%／33.5%**。这是诊断原型的实验依据，正式实现仍需独立验证；授权仅限上述最后一轮。

稳定状态下，选中样式不会改变本批节点端口位置，路径可以保持。**仅凭节点位置未变或没有待执行帧，尚不能保证跨事件几何复用安全**：诊断中人为改变端口布局而不发通知，节点数据和位置都没变，按钮更新正确，旧路径却偏离实时端口 **109.2 世界像素**。此控制用于证明复用条件，不是已确认的生产回归。跨事件几何缓存需要完整的布局／端口失效契约，本轮未建立这一契约。

此外，省掉几何读取会把主要样式计算推到后续帧，无法用同步耗时约 2 ms 宣称完整手势只需 2 ms。现有框选结束移除 `body.canvas-selecting`，配合全局后代 CSS 规则产生的大范围样式重算仍然存在；本轮没有改交互样式、命中或清理逻辑。

## 调用与必要工作

当前调用为 `finishSelection()`／节点点击／空白点击 → `refreshSelectionVisuals()` → `renderLinks()` → workspace 内的 `renderLinksImpl()`。

| 工作 | 选择变化的必要性 | 当前实现与边界 |
| --- | --- | --- |
| 节点 `.selected` | 必须更新 | CSS 使用 outline 和 resize-handle opacity，本批端口世界坐标不变 |
| 连线删除按钮 `.visible` | 必须更新 | `isConnectionSelected()` 判断任一端点被选中；空选应清除 |
| 按钮 `.hover` | 保留现有呈现 | 悬停也有独立入口，不能被选择刷新意外覆盖 |
| SVG path / hit path 的 `d` | 纯选择且几何有效时可以复用 | 当前每条边都重新写入；可写入不代表需要重建 DOM |
| 按钮 left / top | 随端点几何更新 | 选择本身不改变中心；移动、尺寸或端口布局变化会改变 |
| 端口位置 | 依赖当前 DOM 与变换 | 真端口读取矩形并 `screenToWorld()`；占位节点读尺寸并使用 fallback |
| 连线增删、端点变更、控件脱离 DOM | 必须协调 | 原连线缓存负责创建、修复、删除，不能用按钮循环代替 |
| 临时线和刀切轨迹 | 保留原有维护 | 原函数还处理 `.temp`、`.knife-trail`，纯按钮原型未包含这些能力 |

源码位置：[选择呈现](../static/js/canvas/classic/canvas-workspace.js#L3828)、[端口测量](../static/js/canvas/classic/canvas-workspace.js#L3694)、[连线缓存与循环](../static/js/canvas/classic/canvas-workspace.js#L4305)、[交互 CSS](../static/css/canvas.css#L266)。当前 `renderLinks([])` 的 dirty 分支提前返回，也会跳过按钮 class 更新，不能直接用它作为选择命令。

## 两批真实手势测量

[诊断工具](../tools/classic_selection_link_diagnostics.cjs) 在原 HTML 和脚本上运行；所有改写只存在于诊断页面内，且只替换选择呈现期间的连线调用。三个模式：

- `current`：基线原实现。
- `batch-ports`：每次调用先测量所有唯一当前端口，原连线循环随后读取本次结果，保留全部原路径、按钮和缓存协调。
- `presentation-only`：直接更新既有按钮 class 的下界原型。它刻意缺少失效、拓扑和临时线处理，**不作为待交付实现**。

顺序为第一批 current → batch-ports → presentation-only，第二批重复此顺序；每个模式包含 100／1000 节点合法扇入图、99／999 条有唯一 ID 的边，2 次预热、12 次正式采样。共 **144 个正式样本、168 次含预热的真实 Ctrl 框选**，交替选中 `n0` 和空框清空。每次核对选择、按钮可见性、可信鼠标事件、节点 DOM 身份及稳定几何；各测量页保存调用和 PUT 均为零。另有 3 个原始 profile、3 个后补 trace profile、3 个非手势样式隔离控制，均不计入百分位。

环境：Windows 10.0.19045、Ryzen 5 5600XT／12 逻辑核、Node 24.18.1、Headless Chrome 153、1280×900。测量时没有同时运行回归测试。同步计时从真实 mouseup 到选择处理栈之后的微任务；第二帧到第二个 RAF，表示调度机会，不是物理显示延迟。与上一轮“重复同一选择”的采样不同，本轮交替空选，需使用本轮自己的 current 对照。

单位 ms，列内为 p50 / p95：

| 批次／节点数 | current 同步 | batch-ports 同步 | current 第二帧 | batch-ports 第二帧 |
| --- | ---: | ---: | ---: | ---: |
| 1／100 | 12.0 / 15.4 | 9.5 / 15.5 | 15.9 / 19.7 | 13.7 / 21.6 |
| 2／100 | 11.9 / 16.8 | 9.5 / 14.1 | 16.2 / 21.5 | 13.8 / 20.1 |
| 1／1000 | 280.4 / 365.0 | 179.7 / 242.4 | 309.5 / 395.9 | 222.5 / 278.9 |
| 2／1000 | 282.3 / 324.8 | 170.3 / 248.9 | 313.9 / 361.6 | 208.8 / 289.8 |

1000 节点两批 p95 均下降。100 节点 p50 下降约 20%／14%，但首批同步 p95 多 0.1 ms、第二帧 p95 多 1.9 ms，第二批回落；小图尾延迟没有一致改善证据。若未来另行立项，需补充样本确认这一边界。

`presentation-only` 在 1000 节点两批同步 p50 都为 2.0 ms，第二帧仍为 **200.2／203.7 ms**。它的低同步值包含工作推迟，且无通知端口变化会使用过时几何，不能当成安全优化的收益承诺。

## 成本归因与样式隔离

额外 CDP trace 只用于归因，开启 DOM 探针后的总耗时不与轻量样本混合。主渲染线程区间汇总：

| 1000 节点 profile | 同步样式 | 同步布局 | 后续样式 | 后续 RAF |
| --- | ---: | ---: | ---: | ---: |
| current | 230.8 ms | 96.8 ms | 4.3 ms | 15.4 ms |
| batch-ports | 205.8 ms | 0.3 ms | 11.9 ms | 13.7 ms |
| presentation-only | 0.1 ms | 0.3 ms | 211.8 ms | 14.5 ms |

原始非 trace profile 中，current 的连线函数约 310 ms，端口函数累计约 303 ms；batch-ports 的连线函数约 223 ms，其中集中测量约 215 ms。两者每次仍读取 1000 个唯一端口并写入 1998 个 path / hit path 的 `d`。集中读取省去主要的同步重复布局，但几何第一次读取仍会承接已失效的样式计算。DOM 探针是包含时间，不将 getBoundingClientRect、portPoint 与函数总时间相加。

为分离样式来源，在同一 1000 节点页面保留原 CSS、节点 class 更新和 minimap，仅省略连线几何，执行非手势控制：

| 控制 | 后续样式时间 |
| --- | ---: |
| 仅改变选择，不动 body 标记 | 8.7 ms |
| 仅移除已稳定的 `canvas-selecting`，选择不变 | 200.2 ms |
| 同时移除标记并改变选择 | 238.4 ms |

结合 `body.canvas-selecting *` 及其后代 pointer-events 规则，隔离结果支持全局标记解除是本批剩余样式成本的重要来源。控制不是用户手势，不用于性能收益百分比。各 trace 类别存在嵌套／包含关系，不能把样式、布局、RAF 与任务时间相加。CSS 成本仅保留为参考，没有安排优化工作。

## 几何复用和失效规则

三种模式各完成 10 个边界检查。实时端口与可见路径、hit 路径及按钮中心误差容许 **0.001 世界像素**，用于 CSS 数字序列化和缩放浮点舍入；纯选择前后的路径字符串和按钮位置另要求逐项相等。

| 条件／本轮证据 | 几何责任与边界参考 |
| --- | --- |
| 纯选择、空框；路径不变、按钮随集合变化 | 可以复用已完成的几何，但不能只跳过整个连线函数 |
| 真实节点拖动和 resize；端点变化且最终与实时测量一致 | 保留原 dirty-node 几何队列及 endDrag flush；集中读取使用当前坐标和尺寸 |
| 真实平移；世界端点不变 | 不按屏幕位置缓存世界坐标；占位恢复和媒体可见性继续由原导航流程处理 |
| 真实滚轮缩放；原调度后世界坐标误差在容许范围 | 保留原 wheel 几何刷新，不能用“节点 x/y 未变”取消它 |
| 端口 top 改变并调用原布局通知；两帧后正确 | 原 `refreshGeometryAfterLayout()` 继续负责校正；布局变化不局限于模型 x/y |
| 人为无通知端口改变；没有 pendingGeometry | current／batch-ports 能读到新位置；presentation-only 偏差 109.2；pending 状态不是充分有效性判据 |
| 占位无端口及进入视口后真实恢复；几何均重新协调 | 端口 DOM／fallback 来源改变必须失效；不跨占位与真实节点复用端点 |
| 按钮脱离 DOM；原几何路径重新创建 | 保留缓存的 parentNode 校验和修复；下界原型的外部 DOM 引用不足以承担所有权 |

拓扑增删、端点变更、文档替换、暂停／返回与销毁继续由现有 workspace 所有者和几何路径协调。新增选择入口应经过原 `view()` 检查，不建立可写全局缓存或新的生命周期控制器。临时线和刀切维护必须保留；本轮原型没有对它们宣称完整验收。
