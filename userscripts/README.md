# 普通画布 · 旧版按秒费用核算

脚本：`canvas-legacy-cost-filter.user.js`，基于原「普通画布 · 费用日期筛选」1.1.0 改造。

2.1.0 适配独立流水：自动分页读取当前画布全部记录，稳定版本校验避免生成过程中跨页重复或遗漏；旧服务仍读取画布内的 logs。新增“日志恢复”补录后可重新计算，插件日期范围和手动秒价规则保持兼容。

2.0.1 修复主界面嵌入入口：普通画布位于 `static/index.html` 的 `#frame-canvas` iframe 中，脚本必须允许在子页面运行，因此不能使用 `@noframes`。原 2.0.0 误保留了该声明，独立画布页能运行，从主界面进入则可能不注入。

## 使用

1. 在油猴等用户脚本管理器中打开原脚本，将全部内容替换为此 `.user.js` 文件内容并保存。若选择新建脚本，请先停用旧脚本，避免两个侧栏同时运行。
2. 刷新普通画布页面，打开「费用仪表盘」。右侧会出现「旧版按秒 · 日期核算」。
3. 选择日期或使用日历、今天、近 7 天等快捷按钮。日期包含结束当天，按本机时区计算；留空表示不限。
4. 如有「缺少旧版元/秒单价」，展开「补充旧秒价」，选择平台、模型、规格，填写历史单价和适用日期，保存后重算。没有提供任何预设商业价格。
5. 「导出筛选明细 CSV」导出日志 ID、时间、模型、规格、秒数、秒价、金额、来源、待核算原因，以及原账单金额、币种和计费类型，便于对照。

若右侧完全不显示，先确认已打开具体普通画布的「费用仪表盘」，且使用完整的 2.0.1 头部（没有 `@noframes`）；替换保存后刷新整个主页面，让画布 iframe 重新加载。脚本匹配的是画布子页面 `/static/canvas.html`，无须让首页匹配。若侧栏出现但读不到画布变量，检查脚本管理器是否使用页面上下文；保留 `@sandbox raw` 和 `@grant none`。右侧能统计而左侧不变是预期行为：插件不替换原计费函数。

## 核算规则

- 视频采用旧方案：`单价（元/秒）× 视频秒数`，不经过应用现在的视频 Token 计费 hook。图片优先沿用原费用快照，其次使用应用的图片费用计算或历史图片单价。
- 秒价优先级：旧日志的 `per_second` 单价快照 → 调用当时有效的历史 `per_second` 单价 → 插件中手动补充的秒价。Token 单价不会当成秒价。
- 时长优先级：旧 `per_second` 快照的计费数量 → 日志时长 → 请求时长 → 视频返回时长 → 历史任务、输出视频及关联输出任务的时长。只接受大于零的有效秒数；不会使用 `runMs`（生成耗时）、Token 数量或 `-1` 自动时长值。
- 旧快照保留当时的计费秒数；重新推算的记录标为预估，并列出价格和时长来源。若历史请求时长与实际返回时长不同，采用上述旧口径，而不是暗中改用新的计费规则。
- 手动规则精确匹配平台、模型及所选规格，可限定日期；同一规格不接受重叠日期区间，相同区间再次保存用于修改。手动规则只补充缺失价格，不覆盖已有旧秒价。配置保存在当前浏览器、当前网站的本地存储中；可用规则旁的「删除」移除。
- 金额按旧程序的微元口径计算：先将单价舍入到六位小数，再乘数量并舍入至微元；使用十进制整数运算，合计超过安全整数范围时停止显示，不输出失真的金额。
- 失败记录按旧方案排除，缺少秒价或时长的记录列为待核算，不记作免费；当前 Token 方案可能对上游成功、下载失败的任务计费，两种口径因此也可能不同。

插件只读取日志和价格，不替换应用的计费函数，不保存或覆盖画布的 `cost`、`usage`、`video_info`，也不修改左侧原账单。新版统计全部独立流水，旧服务仍受画布保留的日志数量限制；已截断的记录需要通过应用的“日志恢复”从备份补录，没有留存来源的历史不能凭空恢复。右侧结果用于旧方案历史对账，不代表火山引擎当前真实 Token 账单。
